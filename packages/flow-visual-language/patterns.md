# FLOW Editorial Finance Canvas：表达范式

本手册把 2026-10-18 A+C 概念板中的编辑部层级与财务画布表达拆成可复用模式。它约束信息表达，不限定每个项目必须使用同一导航或布局。

## 页面结构

### 编辑部页眉

- 页面标题用衬线字体表达主题；标题下用一行导语说明分析问题或结论边界。
- 期间、事实类别和筛选范围置于标题附近，但在视觉上次于标题与结论。
- 说明“数据是什么/不是什么”的标签应贴近数据，不藏在页面底部。

### 指标组

- 首屏优先显示 3–4 个当前任务必需的指标，单位与比较期紧跟数值。
- 数字使用等宽数字或 tabular numerals；同比/环比变化用文字、符号和语义色共同表达。
- 缺失/不可用值使用原因文字，不以 0 或空白卡片代替。

### 报告画布

- 主分析区使用大块低对比纸面，标题、图表和解释文字构成一个可独立阅读的区段。
- 图表与结论同屏；支持表、定义和来源可到达，不因装饰性卡片而被推至过远位置。
- 页面可采用非对称网格，但每个区块须说明在当前分析任务中的作用。

## 图表表达

- **趋势比较**：用于期间变化；标题点明指标，轴标明期间和单位，图例可直接区分数据系列。末端值标注只用于避免反复悬停读取。
- **构成/堆叠**：用于可加总的组成；保留总量、分类和单位。缺项保留缺失提示，不擅自补零。
- **瀑布/驱动桥**：用于从起点经变化项到终点的守恒关系；明确残差和方向。不存在的因子不得补造。
- **杜邦/因果拆解**：仅表达已定义的数学分解；把“分解”与“因果”区分开。
- **风险/热力**：必须有可追溯定义的分值和色阶；无经核验风险值时不生成装饰性矩阵。
- **同值表**：画布图表旁或紧邻位置提供同一数据的表格/文本形式，支持键盘和辅助技术。

## 色彩语义

- 海军蓝承载品牌框架和主要结构；纸白承载阅读面；古金用于有限强调，不映射成“好/坏”状态。
- 收入、利润、现金等图表系列按语义固定色值；多个公司/期间需要比较时先用线型、标签或明暗区分，避免只靠红绿。
- 正向、负向、警告、信息、不可用分别使用 `semantic` token，同时以文字或图标说明状态。
- 纸面和表格依赖细分隔线与轻层次；避免大面积高饱和渐变、厚阴影和装饰性噪声。

## 图表视觉规格（验收口径，2026-10-29 增补）

多系列图表的观感必须由概念板色板推导，不得引入无出处的第四色相：

1. **系列色阶（`chart.series`，六色，按序使用）**：
   - `#1F4D70` 墨蓝＝`data.revenue`（收入/主指标基准色）；
   - `#A98137` 古金＝`data.profit`（利润/对照系列）；
   - `#398C65` 翡翠绿图表阶＝`semantic-positive(#286048)` 提明度一档（现金及正向序列）；
   - `#9BA6A4` 中性灰绿＝概念板构成图的「其他成本」与次要分类，不承担正负语义；
   - `#C7A471` 金沙亮阶＝`brand-gold` 提明度；
   - `#163B5C` 墨蓝深阶＝`data.revenue` 降明度（与 `brand-navy #18354D` 保持可辨差异）。
   相邻系列按色相/明度错开；超过六系列先用明暗与线型区分，不得新增色相。费用构成使用稳定分类映射：销售＝古金、管理＝翡翠绿、研发＝中性灰绿、财务＝墨蓝，与概念板成本结构的金/绿/灰/蓝层级一致；饼图、堆叠柱与同值图例共用该映射。
2. **画布内文字字族**：轴标签、图例、数据标签、tooltip、仪表盘文字一律 `chart.fontFamily`（Noto Sans SC Variable / PingFang SC）；图表代码必须消费该 token，不得退回浏览器默认字体。
3. **网格与轴**：网格线 `chart.grid #E8E3DA`、轴文字 `chart.axis #777F85`、轴线细于 1px 观感；热力分格边界用 `surface-raised`。
4. **柱形与环形**：柱圆角 ≤4px；环形图内径 48%/外径 72%（玫瑰 28%/72%），标签在环外并带百分比；排名条右端 4px 圆角。
   瀑布桥的「增加」为图表翡翠绿、「减少」为中性灰绿，表示算术方向；只有负向结果或真实风险状态才使用负向语义红。报告环图不得把语义红、警示色当作任意分类系列。
   现金流量净额等按期间分组的柱图，即使某期值为负也保持本期/上期的墨蓝/中性色；经营/投资/筹资三活动柱分别使用墨蓝/古金/图表翡翠绿。均由零轴位置和带符号数值表达正负，避免把流出方向误画成风险判断。
5. **趋势与 KPI 微图**：普通趋势线不使用面积填充；收入与营业利润等同单位序列共享纵轴，只有单位不同或确需独立刻度的场景才使用第二轴。收入与经营现金流使用最近三期中性灰微柱，营业利润使用图表翡翠绿微柱；微柱以零线为基线，正值向上、负值向下，毛利率使用真实比例小环图。
6. **treemap 及任何新增图型**：必须显式绑定本色阶或 semantic token，禁止依赖渲染库默认色板。
7. 修改系列色阶时：改 `tokens.json` 后运行 `scripts/build_flow_visual_language.py` 重新生成三产物，禁止手改任何生成文件。

## 响应式与可访问性

- 桌面可用左右并置的主图与桥/支持区；平板收窄次要内容；手机先显示标题、结论和核心指标，再按分析顺序纵向阅读图表、支持表和来源。
- 图表、表格和页面本体不得造成横向溢出；确需宽数据表时由表区域承担横向滚动并保持首列/列标题可辨。
- 所有交互可键盘到达且有清晰焦点；文字、数据标签与背景符合对比度要求；状态不只用颜色表达。
- 支持 200% 缩放。动态图表提供静态数据表或摘要，不要求动画才能读取数据。

## 示例占位原则

`specimen.html` 只展示色块、文字阶层与布局占位，不包含虚构经营数值或状态。复制到其他项目时，应先替换内容语义，再按业务数据本身选择图表。
