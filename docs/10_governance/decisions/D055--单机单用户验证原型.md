# D055 单机单用户验证原型

- 状态：用户于 2026-10-18 明确选择单机单用户、SQLite 单文件与本地文件目录，并确认视觉方向 A 主风格 + C 报告叙事。
- 当前交付目标：FLOW 优先作为单机单用户的财务分析验证原型，不按复杂企业生产部署、多租户和多角色权限作为本阶段验收条件。D053 的内部月度分析工作流、客观事实、专业治理、证据链及报告原则继续适用；企业级部署与角色权限暂缓，本决策不将其视为本阶段必须实现的架构约束。
- 数据存储：SQLite 单文件作为结构化业务数据的权威存储；内容寻址的原始文件、生成报告和导出包存入本机应用数据目录，并继续校验 SHA-256 与不可变写入语义。Excel 作为交换和备份形式，不作为指标关系、证据与业务流程状态的权威事实源。
- 运行架构：移除本阶段不需要的 Redis、Celery、MinIO 运行依赖。保留已有 Next.js 界面、FastAPI 分析 API、Python 财务计算和 ECharts，提供本机一键启动方式；不引入新的图表库或中间件。若实现审计证明某个现有服务边界可以低风险地直接合并，按工作包验收后再裁决，不以重写界面和计算链路换取表面上的进程减少。
- 用户边界：暂缓多角色、岗位与多租户授权验证；本机单用户身份、登录保护、计算来源和审计事实不得因简化而被静默移除。
- 视觉方向：驾驶舱使用 A「高管编辑部」为主风格（暖白、墨蓝、克制金色与翡翠绿），报告视图吸收 C「财务报告画布」的结论先行与图表叙事。图表继续复用 ECharts。图片只用于真实来源或帮助识别的内容，不作为数据缺失时的装饰性替代；演示数据须持续明确标记。
- 实施先后：先在隔离环境验证 SQLite 模型/迁移、内容寻址本地存储和备份恢复，再迁移单机启动路径，随后完成全部主要页面的图表、数据、交互与追溯验收。既有主线中的后续任务在本工作包关闭前顺延。
