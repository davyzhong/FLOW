# D053 三层两模块边界与执行顺序

- 状态：有效；用户于 2026-09-12/13 经三部分战略讨论逐段确认，并明确授权沉淀为正式决策。

- 决定：FLOW 采用"三层、两模块"结构：
  1. **可见的专业治理底座**：财务事实与会计科目定义、指标/公式/维度/差异分解、分析方法/证据规则/置信度规则、企业字段映射/管理口径/报告配置、知识来源/版本/变更记录。这些是正式产品功能而非隐藏实现，用户可查看任何数字的计算方式与规则来源；
  2. **共享分析底座**：数据接入/识别/映射/校验/对账、确定性财务计算与标准差异分解、AI 探索性计算及程序复算、Finding/证据链/假设/追问/置信度、分析型 AI 与 CFO 角色 AI、报告版本/审核/冻结/导出；
  3. **两个独立产品模块**：公开财报分析模块（先行成熟共享底座）与企业内部分析工作台（最终目标产品）。两者共享专业底座，但拥有独立入口、规格、验收标准和模块 workstream/backlog 视图；公开模块不再定义内部工作台的用户流程。全仓可领取任务、优先级和状态只由 `docs/50_plans/CURRENT_ROADMAP.md` 汇总，模块视图不得成为第二份执行路线图。

- 治理分层：平台标准只读并随版本发布；企业配置可修改和版本化；影响正式计算的规则需要审批；个人显示偏好直接生效；历史报告始终绑定当时的规则版本，不被新配置改写。

- 内部工作台主交互：**工作流为主、对话为辅**（收集资料 → 识别与映射 → 校验与对账 → 自动标准扫描 → 推荐重点 → 深入调查 → 补充证据 → 分析型 AI 生成专业版 → CFO 角色 AI 生成管理层版 → 经分专员一次终审 → 正式发布）。

- 执行顺序（用户已批准）：
  1. **完成 U8**：收口真实存储、发布、HTTPS、部署和运行验收，形成完整、可运行、可恢复的现有版本；新战略文档可同步完成，但 U8 期间不进行核心数据模型、主导航和工作流的大规模改造；
  2. **冻结现有版本并重构边界**：明确共享专业底座、公开财报模块和内部分析工作台的职责，重整规格、导航、唯一路线图和模块命名；先发布向后兼容的 Financial Facts Contract V2（或等价扩展合同）与安全/权限子规格；旧成果保留，不让公开财报流程继续定义内部工作台；
  3. **公开财报模块达到 C 级出口**：公开材料接入、事实计算、自动 Finding、证据分级、分析型 AI、CFO 角色 AI、交互式报告、人工终审、冻结与导出；达到出口后主要开发资源切换到内部工作台；
  4. **建设企业内部月度分析工作台**：持续企业分析空间、Finance BP 轻量提交入口、月度分析周期、企业配置、历史学习和分层报告；
  5. **四级验证**：物流样板端到端 → 专业经分评审 → 与人工报告和工作量对照 → 授权脱敏真实企业数据验证。

- 接替关系：
  - **D045（双轨产品结构）被取代**："财务分析轨 + 经营分析轨"双轨框架由"三层两模块"取代；财务/经营不再作为两条受众轨道拆分，而是同一工作台内的固定分析对象；公开财报分析从主工作流中分离为独立模块；
  - **D046（双轨执行计划三步骤）被取代**：三步骤由本决策的五阶段执行顺序取代；
  - **D049 的阶段定位被修订**：公开财报模块从"当前阶段的产品定位本身"回归为"先行成熟共享底座的独立模块"；D049 的核心约束（客观基础优先、缺失不补造、公开数据不倒造企业分录）继续适用于公开模块。
  - U8 完成后的旧 U9/U10 不机械续跑，先按本决策顺序重新裁决保留、改写、合并或取消。
