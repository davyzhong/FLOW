# D056 K2 即时工作区快照与内容稳定性门禁

- 用户于 2026-10-19 授权取消 K2 固定时段等待，并要求立即简化和修复当前快照流程。
- K2 的 Obsidian 快照可在任意时间启动；不得要求等待 14:30/15:00/15:30。
- 工作树 dirty 不自动等于不安全。快照必须覆盖纳入范围的 tracked、staged/unstaged 与 untracked 文件内容，计算稳定、确定性的内容 SHA-256，并明确标记为 `working_tree`；只记录 Git status 文本不足以证明 dirty 内容已纳入。
- 候选与复验在同一次操作中完成。两次完整内容指纹、HEAD/tree/status 一致且没有实际指向 vault 的写入句柄，才可 accepted。系统进程名称本身不能作为 writer 拒绝条件；无法可靠检查时 fail closed 并给出具体原因。
- `CURRENT_RELEASE`、ObsidianWiki 的文件和 Git 状态不因冻结器而改变。冻结 manifest 与 SHA-256 sidecar 在 Davybase 推送成功前不释放冻结锁。
- K3 消费数据前和完成后都必须与已接受 manifest 的内容指纹核对；任何漂移都停止 candidate，不把后续变化冒充为该快照。
- 该决策只修订 D051 对本次 K2 快照稳定性的执行机制，不改变 Obsidian 作为内部知识源的权威边界，也不授权日常动态读取。
