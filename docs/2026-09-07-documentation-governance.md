# FLOW 文档分类、命名与维护规则｜2026-09-07

状态：当前文档整理规则；不修改产品规格或程序行为。

## 1. 命名

叙述性规格、计划、研究与验收采用 `YYYY-MM-DD-主题.md`。日期优先文档注明的建立/验收日期，否则使用 Git 首次登记日期并在登记说明；不伪造外部文章发布日期。已有合规名称不反复改名。原中文主题保持可读，英文主题使用短横线。

固定导航（README、AGENTS、INDEX、PROJECT_STATE、目录清单）、机器/测试引用的文档、生成文件保持原路径，通过标题与适用元数据标核对日期。它们是有意的稳定入口，不是漏改。原件、批准快照、原始图片与可读转录保留路径和字节；更新在上层索引完成。

文件名日期是建立/归档日期，不是每次修改日期。正文另列更新/适用性核对日期；这样可以排序，也不因日常维护让所有链接反复变化。

## 4. 更新和验证

更新当前说明时核对已提交代码/API/迁移、CI 的具体提交、在途改动和有效决策。原始材料中的错误不得通过改原件抹去。重命名同步可变文档链接；不可变档案中的旧路径通过改名映射追溯，必要时留下兼容入口。

每轮生成全量登记（包括不改动的文件及原因），检查 Markdown 链接、改名目标、固定工具路径、原件哈希、知识库清单和 Git 范围。历史代码示例中已删除的实现路径只标历史，不假造空文件修链接。运行命令若会重建测试数据库必须明确警示，文档任务不得运行它来“验收”。
