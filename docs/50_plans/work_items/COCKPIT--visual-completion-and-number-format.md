# CFO 驾驶舱视觉补全与数值格式治理

## 目标

在已交付的 CFO 驾驶舱路由和真实 API 数据链路上完成可用的图表展示与页面信息补全，修复隔离演示中费用页运行时错误；统一评估并修复前端数字精度，订单/件量等计数显示整数、金额显示两位小数，百分比/比率/天数按业务单位合理显示。该工作是已关闭驾驶舱产品化工作包的视觉验收收尾，不替代其数据真实性、权限和 C 级门禁。

用户已授权按本项及 2026-10-16 项目复核提出的驾驶舱后续步骤连续执行。路线图队列由知识刷新 K0–K6 切换为本项队首，K0–K6 保持排队；不并行、不跳项。

## 实施范围

1. 盘点驾驶舱及关联财务分析页面所有数值格式化点，形成单位/数据类型→显示精度的映射；统一格式工具并替换裸 `toLocaleString`、默认浮点及不合理小数。
2. 修复 `/cockpit/expenses` 在演示数据下对非数组 `values` 调用 `.map` 的运行时错误，并完善契约与覆盖测试。
3. 按已有 51 图映射和 ECharts 6.1.0 构建器，为有足够可用数据的指标补齐图形视图；缺少披露事实的项目保持明确 unavailable，不能造数、补零或伪装为趋势。
4. 增加收入/利润、现金流、资产负债及其它已有期间序列的趋势/比较呈现；对新增、下降、持平或不可比较使用真实 prior 数据，并展示基准期间、单位、来源/口径与缺失状态。
5. 使图表、指标卡和表格支持已具备证据及权限范围内的链接/下钻；没有对应明细事实时，链接至指标定义、来源或明确不可下钻说明。
6. 逐路由检查驾驶舱视觉、内容完整度、加载/空/错误态与窄屏布局，更新对应测试与可复现截图证据。

## 验收标准

- 驾驶舱全部 8 个当前页面在隔离演示种子上无 React/Next 运行时错误；费用分析回归测试覆盖此前非数组 `values` 响应形态。
- 51 图映射中的每项被标为可视化类型及可用状态；可用数据项真实渲染相应图表/指标/表格，不可用项明确说明原因。无纯静态占位图或虚构趋势。
- 订单数、包裹量、客户数等计数按整数格式显示；金额统一两位小数；百分比、比率、倍数、天数和大额单位经领域评估后保持语义一致。极大/极小值、负数、零、空值、非法值测试通过。
- 所有对比变化均使用已存在的可比期间/基准，正确标识新增、增长、下降、持平、不可比较，不把缺失值当零。
- 用户可从至少一项总览指标到模块图表，再到事实/来源或明示的不可下钻状态完成完整交互；页面链接和导航守护测试通过。
- 使用隔离测试数据库与演示数据，报告环境、数据批次和验证代码 SHA；常驻开发/演示数据库不连接、不重置、不写入。
- 文档门禁通过；准确提交 SHA 对应 CI 通过后才关闭此队首。

## 执行顺序

1. 盘点数字类型、单位与格式化路径，先写有代表性的失败测试。
2. 修复格式化与费用页异常，运行模块级单测、typecheck、lint。
3. 按 51 图映射补可视化和真实期间对比，优先复用 ECharts 构建器与现有 API，避免新增逐图请求。
4. 补齐有据可追溯交互及空/错误状态，更新 route/navigation/E2E。
5. 在隔离种子和真实浏览器视口验收所有 8 路由、数字格式、趋势与截图；处理所有失败后再交付。
6. 更新项目状态、路线图、HANDOFF 与图表验收证据，文档 M1、代码验证、同 SHA CI、提交推送均完成后关闭队首，再恢复知识刷新 K0–K6。
