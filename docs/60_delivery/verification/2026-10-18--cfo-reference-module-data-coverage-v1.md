# CFO 参考模块与页面数据覆盖矩阵

## 结论

项目已经具备 CFO 主题页、ECharts 画布、指标字典、公开财报来源和大麦合成经营数据。主要问题不是“没有图表”，而是**同类分析散落在不同入口、事实类别/期间粒度混用、部分图表语义弱于标题、重要分析能力缺数据或没有进入 CFO 总览**。目前不能仅凭页面数量或图表数量认定覆盖完成。

本盘点按当前代码与数据包进行静态核查，没有启动应用、连接数据库或重新采集截图。参考文章《集团财务总监经营驾驶舱》仅作为信息组织和图表形式参考；既有工作包记录文章摘要未逐图核验，因此矩阵不引用其演示数字或将其视为指标定义。既有真实浏览器验收可参见[驾驶舱全视图核验记录](2026-10-17--cockpit-all-views-visual-browser-verification-v1.md)。

## 数据与入口边界

| 数据层 | 当前来源与粒度 | 可支持的用途 | 不应作出的解释 |
|---|---|---|---|
| 公开财务事实 | 菜鸟申请稿 IFRS FY2022/FY2023 报表行与冻结快照，年度/期初期末粒度 | 资产负债、盈利能力、费用、现金流、杜邦等公开财报分析 | 不能扩展成公开披露的月度实际或滚动预测 |
| 公开运营/分部事实 | 菜鸟招股书经营指标及阿里年报分部收入登记，按来源分别为年度、季度 stub 或披露时点 | 运营量、Non-IFRS、业务线和分部趋势 | 不同来源、不同期间定义和单位不能直接拼成同一序列 |
| 大麦经营演示数据 | `data/enterprise/damai-logistics/v2/business/canonical/`；清单登记 24 个期间、1,920 条运营实际、768 条财务实际、10,752 条月度预算等 | 验证月度筛选、经营分解、预算比较、产品/客户/区域分析与导入链路 | 这是明确的 synthetic allocation/演示数据，不是菜鸟真实月度/逐笔披露 |
| 预测侧车 | 大麦 v2 `business/forecast/rolling_forecast.jsonl` | 验证预测数据接口/格式的候选输入 | 当前静态文件不能证明已接入 CFO 现金预测，也不等同于 13 周现金流预测 |

当前入口有两套相邻的总览：导航中的“经营总览” `/` 使用经营分析面板；“CFO 驾驶舱” `/cockpit` 使用财务总览投影。`/` 已有经营利润桥、发现项、产品表现表和毛利矩阵，`/cockpit` 则有财务 KPI、趋势、结论与行动项。用户按导航进入 CFO 驾驶舱时，不会在该页直接看到 `/` 的利润桥和产品/毛利分析，这是入口/信息架构缺口，不应靠再造一份利润桥解决。

## 从映射中发现的关联问题

1. **事实来源和时间粒度是最重要的误读风险。** 同一演示主体名称下存在菜鸟年度财报、阿里年报分部事实和大麦 synthetic allocation；按月、年度、stub 季度与时点数据不可直接连成一条无差别曲线。建议页面通用地展示来源类别、报告/批次、期间粒度和数值状态。
2. **两套总览会拆散同一 CFO 任务。** 利润桥、Finding、产品表、毛利矩阵在 `/`，CFO 财务 KPI、趋势和行动项在 `/cockpit`。建议先统一导航和任务入口，优先复用 `/` 已有分析结果/图表。
3. **图标题与图形语义不总是等价。** 资产结构 treemap 当前只取最新期；负债权益“结构”以两期值形成对比而非占比构成；相关图表需在后续图表设计阶段决定是改名、改图型或补充占比/多期数据，不应只增加颜色/画布数量。
4. **不同主题页面的时间筛选和比较口径不统一。** CFO 总览接受期间视图及维度筛选；若干财报模块固定读取 FY2022/FY2023。页面需明确可比期间与不可筛选原因，避免筛选体验暗示接口实际不支持的维度。
5. **追溯可达性分层不均。** 盈利能力页能深链到字典、快照、财报行；通用模块更多链接财报或披露 fact ID，部分利润桥驱动无独立指标定义链接。可将“数值→指标定义→计算输入→冻结快照→来源行”作为统一链接路径。
6. **数据已存在不代表已经产品化展示。** 大麦 v2 有月度预算、回款、运营实际和月收入预测侧车，但当前公开财报主题 API 仍按年度冻结财报构建。应按事实类型择路接入，不把数据包里存在的字段误报为页面已使用。
7. **覆盖率和功能状态需要区分。** 某指标在 YAML 可计算、某个 API 返回了 KPI、某个图表在浏览器画出，分别是定义存在、数据可算、可视化已交付三种状态；后续路线应逐项追踪而不是合并为一个“完成”。

## 后续设计顺序建议

依照唯一工作包，不在本矩阵中启动实现。建议后续 4.2 先以 12 个既有分析入口建立状态矩阵，区分“已有且数据/粒度匹配”“需要增强入口/追溯”“数据不足”“尚无实现”；4.3 优先考虑整合 `/` 与 `/cockpit` 的利润桥与财务总览、修正图标题/结构语义、统一来源与期间披露；账龄、13 周预测、风险矩阵、合并抵销则先定义所需字段和来源条件，只有确认拿得到对应数据后再决定是否实现图表。指标定义继续复用 `config/metrics/` 现有字典，不在前端另造计算口径。
