## 结论

Phase 6 已忠实实现批准原型的核心信息架构和高密度 Finance BP 工作方式，同时以真实受治理对象替换原型中的示意数字、AI 文案和不受现有数据契约支持的比较口径。最终浏览器复核中发现并修正了三项材料差异：重复页面标题、Findings 脱离分析首行、产品表与毛利矩阵上下堆叠。修正后，桌面版恢复为“八指标 + 三栏分析 + 双栏明细”的批准结构，并保持单一 `h1` 和可访问滚动区域。

参考 HTML 中部分中文因历史归档编码在浏览器中显示乱码；结构、比例、颜色、密度和组件位置仍可用于视觉比对，文案则以正式规格和当前中文实现为准。

## 浏览器交互复核

真实 API 与 Web 启动后，在 in-app Browser 中完成以下检查：

1. 从当月切换到 YTD，地址更新为 `/?period_view=ytd`，选中状态与八个指标同步刷新；
2. 点击“履约成本增加：进入调查”，进入 `/investigations/{finding_id}`；
3. Investigation 回执同时保留 `finding_id`、`batch_id`、`metric_snapshot_id` 和 `analysis_run_id`；
4. 页面只发起同源 `/api/v1/dashboard/overview` 请求，未访问原始文件、canonical、Metric Value 或 Analysis 持久化接口；
5. 1440 和 1920 两个基线均使用真实确定性 bootstrap 数据，而非前端 fixture 常量。

## 有意差异

- 原型中的“预算经营利润桥”改为当前 Phase 5 已发布的 T12 同比经营利润桥；系统不伪造尚未存在的预算 Driver 分析。
- 原型中的数据质量百分比分数改为真实质量状态、问题数量、警告确认和对账状态。
- 原型中的 AI 总结改为确定性的 Finding 摘要；AI 解释和追问属于 Phase 8。
- 页面没有启用尚未实现的模块入口；未来入口以不可交互的“即将开放”状态呈现。
- Investigation 当前为不可变身份回执壳；证据下钻、公式、复核和批准属于 Phase 7。

这些差异都是治理边界的落实，不是视觉或功能遗漏。
