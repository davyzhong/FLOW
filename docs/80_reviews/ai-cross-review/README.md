# AI 交叉评执行包

> Q6/Q7 裁决：纯 AI 交叉评（不同厂商模型），无人工兜底。本包含执行说明、
> 评审 prompt 与结果模板。**评审模型必须是不同厂商**（GPT-5.x / Claude /
> Gemini 任一，不得用 GLM 本体）。

## 证据束

`bundle/` 下 10 份 markdown，每份 = 抽取值清单 + 源 PDF 逐页文本层。
评审 AI 的任务：**在源文本里找出与抽取清单不一致的值**（行名变体、
单位、正负号、期间错位、列读错位均算）。

## 执行步骤

1. 打开一个**非 GLM** 的 AI 会话（上下文 ≥200K）；
2. 逐份粘贴 `bundle/*.md`（单份超上下文时按「抽取清单 + 分段源文本」拆分）；
3. 使用下方评审 prompt；
4. 将 AI 输出原样存为 `results/<模型名>-<日期>.md`；
5. 汇总：实现方对每条报错核对归因（真错 → 修抽取 YAML 新版本；
   误报 → 说明理由），写入 `results/adjudication.md`。

## 评审 prompt（逐字使用）

```text
你是一名严格的财务数据审计员。下面提供两份材料：
1. 「抽取值清单」——一个财报抽取系统声称从某 PDF 中抽取的数值；
2. 「源 PDF 全文」——该 PDF 的逐页文本层。

你的任务：逐行核对抽取清单中的每个数值，找出以下五类错误：
A. 值不存在：源文本中找不到该数值（含千分位/括号负数/单位差异形态）；
B. 值不符：数值存在但抽取值与源文本不一致（含正负号方向相反）；
C. 列错位：数值取自错误的列（本期/上期、期末/期初互换等）；
D. 行错位：数值属于相邻行项目；
E. 单位/口径存疑：抽取值与源文本量纲明显不一致。

注意：
- 源文本已去除千分位逗号与换行，数字可能与其相邻数字连在一起，
  需按上下文判断列边界；
- 括号数字（如 (9,083)）代表负数 -9083；
- 找不到 ≠ 不存在：如整页为扫描图无文本层，请标注「无法核对」而非报错；
- 不确定时标注「存疑」，不要猜测。

输出格式（逐条）：
| 序号 | 类别(A-E/无法核对) | 抽取清单行 | 你在源文本中找到的证据 | 结论 |
最后给出：各类错误计数与总体判断（通过/不通过）。
```

## 独立性纪律

- 评审 prompt 不得包含答案集判定、L0/L1 结果或任何实现方结论；
- 评审模型与实现模型（GLM）不同厂商；
- 结果原样归档，实现方的逐条归因写入 `results/adjudication.md` 并注明
  「接受/误报」理由——误报不得静默删除。
