## 0. 需求重述

用户希望建立两样东西：

1. **基础数据准备**：会计科目、会计分录、会计准则的基础数据；
2. **财务分析指标库**：类似数据字典，记录财务分析报告中的指标及其计算关系（如利润率怎么计算、损益怎么计算）。

系统能力要求：**可查询、可更改、可被观测、可被使用**。

## 1. 核心概念模型

### 1.1 会计基础数据（Accounting Foundation）

三个一层对象：

```text
Standard (准则)                Account (会计科目)              EntryTemplate (分录模板)
├─ code: CAS / IFRS           ├─ code: 1001 / 1122 ...        ├─ scenario: 销售确认收入
├─ version: 2006 / 2024汇编    ├─ name: 银行存款 / 应收账款     ├─ lines: [{方向: 借, 科目: 应收账款},
├─ issuer: 财政部 / IASB       ├─ category: 资产/负债/共同/      │            {方向: 贷, 科目: 主营业务收入},
├─ effective_date             │          权益/成本/损益        │            {方向: 贷, 科目: 应交税费-销项税}]
└─ source_url / document_ref  ├─ balance_side: 借 / 贷         ├─ amount_rule: 金额来源说明
                              ├─ standard_ref → Standard      └─ standard_ref → Standard
                              ├─ parent_code (明细科目层级)
                              ├─ status: 现行 / 已废止 / 企业自定义
                              └─ note: 核算内容说明
```

设计要点：

- **版本化是一等属性**：2006 版 156 科目 → 2024 汇编 171 科目的演进证明科目体系持续变化，每个科目记录其准则版本来源与生效/废止状态（依据：07 号资料第 2、3 节）；
- **双层科目结构**：标准科目（准则规定）+ 企业自定义扩展（准则允许自行增设、分拆、合并），自定义科目必须挂接到标准科目父级（依据：07 号资料第 2 节规则）;
- **余额方向（借/贷）** 是指标取数口径映射的基础。

### 1.2 财务分析指标库（Metric Dictionary）

每个指标是一张「指标卡片」：

```text
MetricCard (指标卡片)
├─ id / code: 如 ROE、GROSS_MARGIN
├─ name / aliases: 净资产收益率（权益净利率）
├─ definition: 自然语言定义
├─ formula: 结构化公式（引用其他指标或报表项目/科目）
├─ unit: % / 倍 / 天 / 元
├─ caliber_version: 口径版本（同一指标的多口径并存，如 ROE 用平均净资产 vs 期末净资产）
├─ source_mapping: 取数来源（报表项目 / 会计科目 / FLOW 数据中间层字段）
├─ dimensions: 支持的维度（组织、客户群、产品、月份...）
├─ time_behavior: 流量 / 余额 / 平均余额
├─ benchmark: 参考区间与行业基准（标注来源）
├─ depends_on: [其他指标 id]  ← 显式依赖边
├─ mpm_flag: 是否管理层自定义口径（若是，须有与法定口径的调节公式）
├─ status: 草案 / 生效 / 废止
└─ provenance: 来源（准则 / 教科书 / 评级机构 / 企业自定义）+ URL
```

指标之间的三类关系：

1. **计算依赖**（depends_on）：ROE ← 净利润、平均净资产；杜邦分解 ROE ← 净利率 × 周转率 × 权益乘数；
2. **口径调节**（reconciliation）：Adjusted EBITDA → 法定利润的调节链（KPMG/EY 对 MPM 的披露要求，09 号资料第 2、3 节）；
3. **分类归属**：偿债 / 营运 / 盈利 / 发展 / 现金流 五大能力域（08 号资料第 1 节）。

## 2. 四项系统能力的设计含义

| 用户要求 | 设计含义 | 对应 FLOW 已有资产 |
|---|---|---|
| 可查询 | 按名称/编号/类别/能力域检索；查公式、查口径、查来源、查依赖；AI 可用自然语言查询 | Copilot 上下文包机制可复用 |
| 可更改 | 修改走「新版本」而非原地覆盖：指标改公式 = 新口径版本 + 旧版本保留；与已发布快照的不可变原则一致 | Phase 4 版本化 metric_definition、D028/D033 不可变消费边界 |
| 可观测 | 每个指标记录：谁在用（驾驶舱/报告/分析 playbook）、当前版本、变更历史；指标变更影响下游的提示 | 变更影响图思想的对象化 |
| 可使用 | 指标卡片直接驱动确定性引擎计算；指标库 = 引擎的唯一口径来源，报告/驾驶舱/Copilot 不允许自带公式 | D016 确定性引擎、D031 分析输出边界 |

## 3. 与现有 FLOW 架构的衔接（关键判断）

**这不是另起炉灶，而是把已有的指标语义层从「硬编码目录」升级为「可治理的指标库」。**

- 现有 `flow.metrics.logistics.v1`：15 个指标、14 条依赖边、版本化 metric_definition、不可变快照——本质是指标库的 V0（物流场景、代码内冻结）；
- 本设计的指标库是它的**通用化与数据化**：指标从代码迁移到数据库对象，增加口径版本、来源映射、基准、MPM 调节、审计；
- 会计基础数据是**新增底座**：当前数据中间层是经营事实表，没有会计科目层；引入科目/分录后，可支撑「从总账/科目余额表直接取数」的新数据通道（V1 当前只走标准 Excel 模板通道）；
- 不触碰的边界：已发布快照不可变（D028/D033）、Finding 审批资格（D037）、AI 不创造数字（D016/D031）。

## 4. 分期建议

- **P1 数据与模型**：准则/科目/分录/指标卡片的数据模型 + 权威初始数据集（CAS 2024 汇编 171 科目、五大能力域约 40 个通用指标 + 物流行业指标、杜邦依赖图）；
- **P2 查询与治理**：检索 API + 只读浏览界面 + 版本化变更流程（草案→生效→废止）+ 变更审计；
- **P3 使用闭环**：指标库替代代码内指标目录，成为引擎、驾驶舱、报告、Copilot 的唯一口径来源；打通「科目 → 指标取数」映射；
- 与当前 Pilot Phase 2（安全部署）并行不冲突，但真实数据试点结论（D038/D039）仍优先决定 V1.1 范围。

## 5. 决策点（2026-09-05 用户已逐项确认，记为 D040）

1. **范围**：会计基础数据做「查阅级 + 取数映射」，不做核算级总账；核算级留待试点证据。**已确认**；
2. **准则覆盖面**：CAS + IFRS 对照（IFRS 至少覆盖 MPM 等关键概念）。**已确认（用户选择纳入 IFRS）**；
3. **指标库初始规模**：通用 40 指标 + 物流行业 15 指标起步。**已确认**；
4. **与 V1 指标目录的关系**：指标库建成后，`flow.metrics.logistics.v1` 迁移为库内「行业指标集版本」，保持单一口径来源。**已确认**；
5. **生效节奏**：与 Pilot Phase 2 安全部署、脱敏真实数据试点并行。**已确认**。
