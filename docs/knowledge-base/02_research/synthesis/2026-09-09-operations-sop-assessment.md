# 分析判断｜《终于有人把经营分析给说清楚了！》SOP 的正确性与 FLOW 适配｜2026-09-09

状态：分析结论。原文档案见[../original/2026-09-09-operations-sop-article](../original/2026-09-09-operations-sop-article/)；采纳结果见 [D050 决策](../../04_decisions/DECISION_LOG.md) 与[经营轨方法论规格](../../../superpowers/specs/2026-09-09-operations-track-methodology.md)。

## 结论

**该 SOP 正确、结构完整，可作为 FLOW 经营分析轨（双轨第二轨）的搭建方法论骨架采纳**；但必须做三项 FLOW 化适配——数据可得性分层、拆解纪律对齐 U2 原语、发布链映射到冻结机制。未经适配直接照搬会把经营轨带偏（财报场景无过程数据可拆、BI 导出绕过冻结链）。

## 一、资料内容还原（三块）

1. **主线长文《如何搭建经营分析体系？》**：以「黄焖鸡米饭」为例提出 MVP 拆解法——先找到让生意跑起来的最小流程（获客→服务→成交），核算收入与固定/可变成本，再给关键经营要素打标签加维度、看过程加指标（收入=门前人流×进店率×成交率×交易金额），最后按手段扩展 MVP（增渠道/增品类/增客单价/降价）逐步丰富像积木。诊断常见病「既不经营，也没啥分析」：KPI 公式一拆就表演归因、模板传家。
2. **实操篇《搭建经营分析看板的流程》**：三步——梳理指标建体系（业务逻辑法 AARRR + 指标拆解法杜邦，补全埋点）、规划看板结构（先总体后细分；核心指标在前解释指标在后；销售/流量/区域/用户/品类/商品六板块）、Tableau 落地（订单+目标+用户+流量四表，派生指标显式定义，达成率/趋势/异常分析纪律）。
3. **《经营分析体系搭建 SOP》8 步总图**：明确目标与业务问题 → 梳理指标体系（战略结果/经营过程/执行行为三层）→ 数据规划与采集 → 数据处理与建模（口径统一）→ 分析方法应用（描述→诊断→预测→推荐）→ 可视化呈现 → 结论输出与建议 → 落地执行与持续优化；基础原则：业务导向、数据真实、口径统一、价值驱动、持续迭代。
4. **增长质量判据（散见于长文后半）**：良性 vs 劣质增长（活动后留存、投产比趋势）、产品分类（品类×价格带）、用户分级（频次×金额四象限、渠道 CAC/LTV）、业务事件簿（常规投入 vs 增量投入分账、经营分析会闭环）、五环闭环（目标监控→经营诊断→原因定位→方案制定→方案验证）。

## 二、正确性判断

### 与 FLOW 已验证原则同频的部分（采纳）

| SOP 观点 | FLOW 对应 | 判断 |
|---|---|---|
| 指标体系文档必须含「定义、口径、计算逻辑」；口径统一是基础原则 | D048 指标库内化 + I12 口径标签登记制 | 正确，且 FLOW 走得更严（未注册口径拒绝） |
| 指标分三层（结果/过程/行为） | D049「客观事实→推断→行动」分层；U2 原语的适用范围标注 | 正确；FLOW 需补「数据可得性」维度（见修正 1） |
| 加法拆解之和须还原总额 | U2/C08 可加和守恒桥（残差显式禁止凑整） | 正确，FLOW 已实现且更严 |
| 「12/31 异常即使同期因元旦下降也不应直接归因于假期」 | C14「相关性≠原因」、I09 联动提示仅提示复核 | 正确，与 FLOW 异常归因纪律完全同频 |
| 业务事件簿：常规投入与增量投入分账、避免规则重叠、经营分析会闭环 | Investigation 事件模型 + D046 经营轨数据定义 | 正确且是 FLOW 经营轨缺失的一等公民数据（活动/事件表），直接采纳进数据定义 |
| 五环闭环（目标监控→诊断→定位→方案→验证） | Finding→Evidence→Conclusion 状态机 + 后续行动闭环（未来项） | 前两环与现有 Investigation 同构；方案/验证两环属行动层，按 D049 后置 |
| 看板「先总体后细分、核心指标在前解释指标在后」 | /operations 页面信息架构 | 正确，直接作为经营轨页面布局原则 |
| 描述→诊断→预测→推荐的分析分层 | D049：客观事实→推断→行动 | 分层正确；预测/推荐 FLOW 明确后置（U9 之后，预测依赖与确定性公式分开） |

### 需要 FLOW 化修正的部分（采纳前提）

1. **数据可得性分层（最重要修正）**。SOP 默认数仓数据完备（埋点、订单、流量表都有）；FLOW 经营轨当前数据源是公开财报，只有结果层数据。财报场景下「收入=人流×进店率×成交率×客单」不可算——FLOW 铁律「缺失不补造」「无量价数据不生成量价桥」。因此方法论必须把每个主题/指标标注数据可得性：财报可得（L1 结果层）/ 内部数据授权后（L2 过程层、L3 事件层）/ 行动层（L4）。公开财报期只建 L1，L2/L3 注册占位但标 `not_applicable`。
2. **拆解纪律对齐 U2 原语**。SOP 的乘法链拆解（UV×转化率×客单价）在 FLOW 只允许在显式量价数据存在时执行；C07 CAGR、C08 守恒桥、C06/I12 口径与阈值标签全部复用，经营轨不自建第二套计算原语。
3. **发布链映射**。SOP 步骤 6–8 是 BI 工具视角（Tableau 导出、迭代看板）；FLOW 按资产纪律映射为：指标快照 → 客观分析条目 → 冻结 Report Snapshot → 发布尝试。经营轨报告沿用同一冻结机制，不建第二套渲染/发布路径（B/S 纪律与 E01/E02 已定）。
4. **「劣质增长砍投入」是行动建议不是客观结论**。良性/劣质判据中可客观化的部分（活动期收入增量、活动后留存、投产比趋势）固化为 L3 关联信号；「砍投入」决策按 D049 属行动层，主观证据门禁（U5）建成后才可入报告，且必须携带假设标注。

### 不采纳/后置的部分

- **预测性、推荐性分析**：当前不建（D049、U9 之后）。
- **AARRR 模型**：面向线上增长业务，与 FLOW 首批经营轨样本（公开财报的物流/电商公司）适配度低，仅在 L2 内部数据接入后按行业选用；不进默认推荐。
- **Tableau/PBI 工具链**：方法论有效载荷（指标分层、看板信息架构）采纳，工具实现由 FLOW 自有 B/S 链承担。

## 三、可用性结论

SOP 与 FLOW 财务轨已沉淀的原则高度同频（口径、分层、守恒、归因纪律），说明其方法论内核是可靠的；它补上的关键缺口是**业务视角的框架**——MVP 拆解法回答了「经营轨指标从哪里来」（从最小生意流程来，不从财报科目倒推），业务事件簿回答了「经营分析区别于财务分析的数据是什么」（增量投入与事件的台账）。这两点正是 D046 经营轨数据定义提炼工作缺的骨架，故按 D047 默认推荐策略采纳为经营轨方法论，适配修正以 D050 登记。
