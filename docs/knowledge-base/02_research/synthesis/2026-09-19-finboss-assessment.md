# FinBoss 财务领域内容评估（外部项目输入）

> 来源：同级工作目录项目 `finBoss`（企业财务 AI 信息化系统，Phase 4/9；用户自有项目）。
> 评估方式：通读其知识库初始化脚本（17 条财务知识）、AR 服务、归因服务、数据质量
> 管道、NL 查询 prompt 与三层建模 schema。**只吸收领域知识与口径设计，不复制代码、
> 不引入依赖**。登记为统一计划借鉴附录 **#26**。

## 1. 来源定位

FinBoss 与 FLOW 同属财务分析，但数据面不同：它吃金蝶/银行等 **ERP 单据级业务数据**
（ClickHouse raw/std/dm 三层），做 AR 应收分析、客户 360、归因与 NL 查询；FLOW 吃
**公开财报**，走确定性引擎 + 治理指标字典路线。因此其价值集中在 FLOW 尚未覆盖的
**企业内部应收信用子域**——即 T13 内部工作台的领域语言，对公开财报模块无直接输入。

## 2. 采纳项（按价值排序）

1. **AR 应收信用域知识（17 条知识库条目）**：科目规则（1122 应收账款 / 1231 坏账
   备抵）、口径定义（AR 总额、逾期金额、逾期率、回款率、DSO、逾期天数三档分层）、
   业务规则（超账期四级催收流程、信用额度动态管控、收入确认四条件、坏账核销三情形、
   对账差异处理原则、六大分析维度）。FLOW 指标字典现有 dso_days/ar_turnover 仅为
   财报口径（报表行项目可算）；单据级账龄/逾期/信用口径为空白 → 作为 **T13 的 AR
   子域设计输入**。
2. **账龄分桶与逾期判定的确定性口径**：五桶 0-30/31-60/61-90/91-180/180+；
   逾期判定含客户类型宽限（常规 30 天）。纯确定性、口径显式，符合 FLOW 引擎确定性
   原则——T13 建 AR 经营事实时作口径参照。
3. **归因服务骨架**：「LLM 生成双维度假设 → 确定性 SQL 模板验证 → 结果集质量置信度
   评分」（有数据 +0.3、样本 >5 +0.2、有变化 +0.3、变化显著 +0.2）。「假设可自由、
   验证必须确定、置信度可解释」与 FLOW O-02 同构；其置信度评分纯函数在 FLOW 调查
   归因需要证据强度标注时可参考。
4. **行业参考值候选**（制造业逾期率 <15%、零售 <10%、上市公司 <5%、DSO 制造
   45–90 天等）：可按借鉴 #21 模式进指标库行业参考包——**但 FinBoss 自身系整理
   性质，数值未经权威溯源，入包前须核验出处，否则标注「待查证」**。本次不入包。

## 3. 不采纳项（留档防重复评估）

- **NL→SQL**（nl_query_service + few-shot prompt）：与 FLOW「敢采信」路线相悖；
  五维矩阵结论即行业正从自由生成转向语义治理，FLOW 已以 O-01/O-02（治理字典提名
  →沙盒复算）替代该路线。留作对照样本。
- **技术栈**（ClickHouse/Milvus/Ollama/Flink/dbt/SeaTunnel）：FLOW 已定型
  PostgreSQL + 确定性引擎，不引入第二套基础设施。
- **数据质量规则**（非空/正值/去重 + pass_rate）：FLOW intake 质量检查（阻断/
  警告/转换规则/勾稽对账）为超集。
- **飞书机器人**：FLOW 无 IM 出口规划；T13 远期作分发渠道候选再议。

## 4. 边界与红线

- FinBoss 知识条目为整理性质（非权威准则原文），凡引用其数值一律标「待查证」；
- 不复制代码；不改变 FLOW 公开财报模块的任何既定口径；
- AR 子域知识只服务 T13（gated），不提前进入公开模块；
- 内部数值红线不变（FinBoss 无菜鸟/阿里内部数值，与 [[U9]] 红线无交集）。
