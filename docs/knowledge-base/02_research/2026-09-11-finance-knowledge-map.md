## 1. 八个知识域与 FLOW 落点

### K1 财务报表基础（三大报表、科目、勾稽）

- **内容**：三大报表结构、科目分类、勾稽关系、报表阅读方法。
- **FLOW 落点**：B 系列来源与财务事实（抽取/归一/勾稽）、U4 独立全行验证、报表中心的三表呈现。
- **已入库**：`processed/03_财务与会计/` 下《掌握这些基本原理轻松读懂三大报表》《财务报表的三大逻辑切入点：盈利质量、资产质量和现金流量》《财报分析框架》《三大财务报表的分析方法与关注要点解析》。

### K2 财务分析方法（比率/杜邦/趋势/结构/现金流）

- **FLOW 落点**：U5 客观报告三章节叙事、四问工作台的「发生了什么/为什么」。
- **已入库**：同目录《财务分析必看的8个模型》《财务思维-如何分析企业的盈利能力营运能力偿债能力和增长能力》《杜邦分析法-拆解企业盈利能力的财务显微镜》《现金流分析-基础知识优势和步骤》《经营活动现金流-公司真的挣到钱了吗》《一文讲透如何写出一篇有深度的财务分析》《如何写一份财务分析报告》。

## 2. 存取与入库协议

**取用（工作协议，2026-09-12 用户确认）**：**此后每次做计划、做功能、做更新，均以 Obsidian 为内部知识来源**。具体门禁为：默认引用 `obsidian-2026-09-12T15:46+08:00`；按 K1–K8 域定位（优先 wiki，必要时回溯 `processed/`）；读取对应 HIGH 明细与 W4 评估；在计划/规格/变更说明中登记采用、拒绝及理由；会计口径仍核对官方原文。只有用户明确要求或单独维护时才建新截面并读取增量。涉及菜鸟/阿里内部资料仅作方法论参照，内部数值一律待 U9/O5 授权，不进产品与对外材料。

**知识治理覆盖层**：K1–K8 描述“读什么”，治理层约束“怎么用”。每条产品化候选至少记录来源路径、截面、知识域、权威级别、敏感级别、适用数据层（L1–L4）、目标 U/O 任务和处置结论。Obsidian 不可访问时不得假称已复核，应显式登记“内部知识源不可用”，继续依正式规格与官方来源工作，恢复后补做差异检查。

**入库**（新增知识）：
1. 抓取公开文章全文为 Markdown，frontmatter 必含 `title` / `source` / `author` / `clipped` / `tags`（YAML 闭合，`tags` 带 `财经分析知识库`），放入 `/Users/qiming/ObsidianWiki/Clippings/`；
2. 在 davybase 仓库执行 `python scripts/run/run_clippings_classify.py`（注意：该命令**直接执行无预览模式**，LLM 分类并移动文件到 `processed/{分类}/`，需 qwen/zhipu API key）；
3. 分类结果落 `processed/` 后，在下次固定截面增量读取时更新本文与扫描评估，不追逐同步中的实时数量；
4. 结构性综述（知识地图、专题汇编）直接写 vault `wiki/` 目录，不走分类管线。

**边界**：vault 由 davybase 与个人日常共用，FLOW 会话只新增/读取本协议涉及的文件，不清理、不重构他人目录。
