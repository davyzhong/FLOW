## 二、五个资料来源共同揭示的"财务分析产品"设计语法

把 71 张图放在一起看，可以提炼出一套高度一致的产品设计语法——这五份资料相当于同一方法论的三个载体（驾驶舱 / PPT 报告 / agent skill）：

### 1. 结论先行（最重要的一条）
- 驾驶舱每页底部有一句"经营结论"（如"利润缺口主要来自毛利率和费用"）；
- PPT 每页标题就是结论句（如"OEE降至72.6%，80%的缺口来自可用率和速度损失"）；
- huashu-excel 报告首屏标题直接写判断（如"表面的营收增长是新品补出来的"）。
- **推论**：我们的产品核心资产不是图表库，而是**"数据→判断句"的生成能力**。

### 2. 归因范式：瀑布图 + 因子分解
预算差拆成价格/销量/结构/成本/费用（资料一、四）；收入缺口拆成时间性/结构性差异（资料三）；成本差拆成材料价格/材料利用/人工效率/制造费用（资料四）；毛利变化拆成采购/结构/调价/返工（资料三）。**瀑布图是全套资料的灵魂图表**。

### 3. 双基准对比
每个指标同时给"同比"和"较预算/较目标/较上月"。指标卡四件套：本期值 + 同比 + 环比 + 预算完成率。

### 4. 异常必须挂"钱、人、期限"
风险/异常条目统一格式：事项 + 影响金额 + 责任人 + 截止日 + 状态（待处置/处置中/待验证/已闭环）。资料四甚至有"收益验证"机制（措施到底赚回多少钱，已验证 286 万/待验证 574 万）。

### 5. 数据可信是前置工程
- 资料一/四：数据中心（4 张中国报表模板、字段映射、勾稽校验、批次管理、质量得分）；
- 资料五：体检（openpyxl 读原始单元格）→ 表内合计对账 → 外部基准对账 → 独立 agent 质控；"AI 算错不会报错"是第一性问题。
- **推论**：用户设想的"后台数据处理系统"应该做成"数据可信流水线"，而不只是 ETL。

### 6. 指标即配置
资料四的指标中心给出完整指标元模型：**编码 + 名称 + 单位 + 计算公式（SQL 风格）+ 聚合规则 + 阈值（红黄绿）+ 血缘 + 变更影响分析 + 审批流 + 版本**。这就是"指标定义系统"的行业标准答案。

### 7. 报告的两种体裁
- 经营分析型（资料二）：问题→归因→因果链→P0/P1 行动→30/60/90 机制；
- 财务述职型（资料三）：结论→分析→治理（税务/内控/投资）→下月计划→**管理层决策事项**。

## 三、对我们产品形态的初步判断（待讨论）

三个目标实际上是一条流水线的四层：

```
┌─────────────────────────────────────────────────────┐
│  ③ 前台呈现：Web 驾驶舱（多维筛选/下钻/预警/行动闭环）      │
│     + ④ 报告生成：HTML/PPT 分析报告（结论式叙事）          │
├─────────────────────────────────────────────────────┤
│  ② 指标层：指标定义系统（公式/口径/阈值/版本/血缘）         │
├─────────────────────────────────────────────────────┤
│  ① 数据层：Excel/CSV 导入 → 体检/清洗/对账 → 数据集        │
└─────────────────────────────────────────────────────┘
```

- 资料一证明了"单机单文件离线"的轻形态可行（卖模板的打法）；
- 资料四证明了"平台化"的重形态（多数据源、审批流、多用户）；
- 我们要做的介于两者之间，**具体取哪个形态是第一个要讨论的决策**（决定技术栈、部署方式和商业模式）。

## 四、待与用户讨论确认的问题清单

1. **产品形态**：单机离线（资料一路线）还是 Web 服务（资料四路线）还是"本地优先 + 可选云"？
2. **目标用户优先级**：总经理、财务总监、财务 BP 三类人，MVP 先做谁的一屏？（资料一是 CFO 视角，资料四是 CEO 视角，内容取舍差别很大）
3. **数据入口**：第一版只支持"4 张中国财务报表 Excel"（最标准、最快做出专业度），还是要支持业务系统导出的任意表格？
4. **分析深度**：静态指标+归因（资料一水平）还是带滚动预测/情景测算/问题闭环（资料四水平）还是带 agent 自动挖掘（资料五水平）？
5. **报告生成**：先 HTML 还是先 PPT？报告是"模板填充"还是"AI 叙述生成"？
6. **商业模式**：自用工具 / 交付型项目 / 标准化产品（模板售卖 or SaaS）？
