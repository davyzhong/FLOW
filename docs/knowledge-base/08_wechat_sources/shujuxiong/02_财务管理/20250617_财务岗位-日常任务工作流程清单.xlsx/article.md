## 一、表格全景

| 维度 | 设计理念 | 价值速览 |
|---|---|---|
| **岗位** | 聚焦 10 大核心职能，覆盖“钱进钱出、核算报表、分析决策、风险管控”四条主线。 | 沟通半径清晰，谁负责一眼可见。 |
| **日常任务** | 划到“半天可完成”颗粒（Total 40 条），不会过粗也不过细。 | 方便列成待办、挂 SLA、接脚本。 |
| **关键工作节点** | 用 6-8 步闭环：校验 → 执行 → 异常 → 归档 → 通报。 | 拆穿“凭经验”黑箱，每步可稽核可优化。 |
| **系统 & 自动化机会** | 命名所有系统（ERP/网银/BPM 等）并标注 RPA、API、OCR 切口。 | IT 部门无需再访谈，直接评估 ROI。 |
| **输入 / 输出** | 统一文件形态（PDF、XML、影像）和数据口径。 | 消灭“发你个 Excel 美化下”式扯皮。 |
| **频率 / KPI** | 周期 + SLA + 质量指标 = 三维管理。 | 让绩效考核与流程监控用同一把尺子。 |
| **风险点 / 责任链** | 高频雷区 + 责任人 + 复核人。 | 天然成为审计底稿索引，问责有章可循。 |

## 二、字段详解 & 示例

> 示范：出纳｜任务 CA-01「网银付款执行」

| 字段 | 示例内容 | 运营贴士 |
|---|---|---|
| 触发条件 | “ERP 付款指令 *已走完* 审批流” | 建议写到“动词 + 状态”，杜绝模糊起点。 |
| 主要输入 | 付款申请单 / 指令号 + 供应商账户 | 可在表格里放超级链接直指影像或台账。 |
| 关键节点 | ① 二次校验授权额度 ② 网银批量导入收款清单 ③ 系统黑名单校验 ④ 双人复核 OTP ⑤ 下载回单 & 影像上传 ERP ⑥ 付款日志留痕 | 步序加 **序号** 方便审计抽样。 |
| 系统 / 工具 | ERP、企业网银、UKey、RPA Bot | 多系统时用顿号，便于后期做数据流图。 |
| 输出 | 回单 PDF、付款成功截图、系统流水号 | 输出要写“是什么 + 存哪 + 给谁”。 |
| 频率 / 截止 | **实时 ≤ 2 小时**内完成 | SLA 最好带数字：时点/天数/T+N。 |
| KPI | 付款准确率 100%、重付率 0 | 如果想做“金字塔”评价，可加权分。 |
| 风险点 | 重复付款、账号输错、超授权 | 更多风险＝更易定 RPA 校验规则。 |
| 自动化机会 | “RPA 自动填单 + 黑名单 API” | 用动宾结构，IT 一看就知道做什么。 |
| 责任人 / 复核 | 李珊 / 财务主管 | 责任到人，复核是“最后一道锁”。 |

## 四、落地小贴士

| Step | 做法 | 关键注意点 |
|---|---|---|
| 1. 确认字段 | 字段不要超过 15 列，太多会不维护。 | 本模板 14 列已涵盖 95% 场景。 |
| 2. 校对名词口径 | ERP 科目、报表名称、文件编号要 **和系统一致**。 | 防止后期接口对接找不到字段。 |
| 3. 给任务打版本号 | 例：`CA-01-v1.2`；系统改版时只升小版本。 | 方便历史追溯、防止错用旧流程。 |
| 4. 引入数据验证 | Excel 里对 KPI、频率做下拉选项/条件格式。 | 杜绝手写自由发挥。 |
| 5. 周度 Review | 每周将“未达 SLA”“风险触发”自动汇总到周报。 | 养成 **PDCA** 闭环。 |
