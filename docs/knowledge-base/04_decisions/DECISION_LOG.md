# FLOW 完整决策日志

状态定义：

- **有效**：当前设计仍然采用；
- **被取代**：曾经考虑或确认，但后来被明确修改；
- **未来**：长期方向，未进入 V1；
- **未决**：尚未进入最终选择。

## D001 产品不是单一驾驶舱

- 状态：有效
- 决定：长期产品方向是 AI 原生的 Finance Intelligence OS；驾驶舱、Excel 分析和报告只是消费、分析和发布界面。
- 原因：参考资料共同显示，真正价值来自数据可信、统一指标、专业诊断、Finding、证据和行动/发布闭环。

## D002 V1 产品定位

- 状态：有效
- 决定：V1 是面向物流供应链企业 Finance BP 的月度经营分析工作台。
- 原因：需要用一个真实行业和完整工作流验证产品，而不是直接建设通用平台。

## D003 部署方式

- 状态：有效
- 决定：不把纯本地离线作为产品前提，架构保持部署方式中立。
- 原因：用户说明本地离线只是实现手段，不是目标；Web、应用或其他部署都可接受。

## D004 项目名称

- 状态：有效但品牌释义未决
- 决定：工程和工作名称使用 FLOW；长期类别名使用 Finance Intelligence OS。
- 原因：FLOW 具有财务逻辑、经营和工作空间的联想，但正式英文展开不影响 V1。

## D005 首版行业与业务

- 状态：有效
- 决定：物流企业，供应链业务。
- 依据：六张供应链规模日报截图以及用户明确选择。

## D006 首版数据真实性

- 状态：有效
- 决定：使用高度拟真的模拟数据，不使用截图中的具体企业真实数据。
- 原因：当前只有截图和摘要，需要能够植入完整预算、财务、应收和现金逻辑并保证对账。

## D007 时间范围和粒度

- 状态：有效
- 决定：12 个月月度历史 + 年度月度预算；暂不做日度和滚动预测版本。

## D008 首版经营故事

- 状态：有效
- 决定：订单与收入增长，但盈利质量和现金恶化。
- 驱动：低毛利业务结构增长、履约成本上涨、战略客户回款变慢。

## D009 分析维度

- 状态：有效
- 决定：客户群 × 物流产品是核心双维度；月份、区域、客户和组织是辅助维度。

## D010 首版用户视角

- 状态：有效
- 决定：只做 Finance BP 主视角。
- 被取代方案：曾选择管理层 + Finance BP 双角色，随后用户明确撤回，要求先做 Finance BP 驾驶舱。

## D011 驾驶舱首页结构

- 状态：有效
- 决定：总览 + 异常 + 专题下钻。
- 原因：匹配 Finance BP“先看全局、再找问题、最后查原因”的工作方式。

## D012 默认分析周期

- 状态：有效
- 决定：当月 + YTD，同时展示预算差、同比和近 12 个月趋势。

## D013 指标组织方式

- 状态：有效
- 决定：经营与财务联动，不采用纯财务结果或纯运营规模。
- 链路：订单/履约量 → 收入/结构 → 单均收入/成本 → 毛利/利润 → 应收/回款/现金。

## D014 驾驶舱信息密度

- 状态：有效
- 决定：采用 Finance BP 高信息密度界面。
- 具体表现：8项核心指标、多种比较口径、趋势、利润桥、Finding、经营明细和交叉矩阵同屏。

## D015 外部驾驶舱参考方式

- 状态：有效
- 决定：同时借鉴参考图的蓝白企业财务视觉和功能信息结构。
- 限制：不降低 FLOW 的分析深度，不复制第三方品牌和内容。

## D016 智能分析方式

- 状态：有效
- 决定：确定性计算引擎 + AI 解读。
- 被拒绝：预设静态洞察；完全由 AI 自主计算和分析。

## D017 Investigation 形态

- 状态：有效
- 决定：异常进入独立 Investigation 页面，专业分析流程为主，AI 对话为辅。
- 被拒绝：仅侧边抽屉；以聊天框作为主要分析界面。

## D018 Investigation 信任机制

- 状态：有效
- 决定：加强证据与复核，公式、口径、血缘、源记录、假设和审阅状态是一等对象。
- 发布规则：关键证据未确认时，Finding 不得进入正式报告。

## D019 Excel 导入进入 V1

- 状态：有效
- 决定：Excel 上传、字段映射和数据清洗是 V1 关键能力。
- 被取代方案：早期曾选择 V1 只使用内置模拟数据，不做导入；用户随后明确要求把导入和清洗纳入 V1。

## D020 Excel 识别方式

- 状态：有效
- 决定：AI 识别 + 引导确认。
- 约束：只支持约定数据域和可识别结构，不承诺任意复杂 Excel。

## D021 单批次文件形式

- 状态：有效
- 决定：V1 每个分析批次使用一个多工作表 Excel 文件。
- 未来：多文件自动合并。

## D022 标准模板与数据中间层

- 状态：有效
- 决定：所有外部数据先填写或转换到 FLOW 标准数据契约，再进入分析。
- 关键澄清：Excel 模板只是外部交换形式；数据库标准表才是真正的数据中间层。

## D023 数据中间层建模

- 状态：有效
- 决定：主题事实表 + 共用维度表。
- 被拒绝：单一经营宽表；V1 直接采用完整业务事件模型。

## D024 标准 Excel 数据包结构

- 状态：有效
- 决定：模块化单工作簿，分为核心必需、财务管理扩展和物流运营扩展。
- 原因：同时获得标准化、经营财务贯通和按场景控制复杂度。

## D025 报告输出进入 V1

- 状态：有效
- 决定：PPT、分析 Excel 和正式月报是 V1 重要能力。
- 被取代方案：最初曾放到后续阶段，用户明确要求纳入 V1。

## D026 报告生成机制

- 状态：有效
- 决定：专业模板 + AI 编排。
- 被拒绝：纯固定模板填数；AI 完全自由生成。

## D027 正式月报格式

- 状态：有效
- 决定：V1 为 HTML/PDF；Word 作为后续扩展。

## D028 统一发布对象

- 状态：有效
- 决定：PPT、Excel 和正式月报共享 Metric Snapshot、Charts、已批准 Findings 和 Evidence。
- 原因：保证多端口径一致并可追溯。

## D029 V1 开发策略

- 状态：有效
- 决定：端到端窄切片。
- 说明：完整跑通导入、标准化、驾驶舱、Investigation 和报告，但只覆盖一个明确物流供应链月度场景。
- 被拒绝：先做厚数据中心再逐模块建设；多个模块无统一主线地并行展开。

## D030 当前设计批准状态

- 状态：历史门槛，已满足
- 决定：FLOW V1 完整产品蓝图已通过用户选择 A 批准，并写入正式设计规格。
- 后续状态：用户已批准进入详细实施并授权按推荐方案连续推进，Phase 1–5 已据此完成；本条不再是当前阻断项。

## D031 Phase 5 分析输出边界

- 状态：有效
- 决定：Phase 5 只生成由确定性计算和已有证据完全支持的 Finding；缺字段或分析不适用时显式降级，不生成假设性 Finding。
- 原因：财务金额、Driver、影响和排名必须可重现，AI 只能在后续阶段解释已有结果。

## D032 Phase 5 分析架构

- 状态：有效
- 决定：采用 typed analysis playbooks + shared protocol，不使用单体硬编码服务，也不在 V1 引入通用公式 DSL。
- 结果：首批注册 `revenue_vpm`、`fulfillment_cost_rve`、`gross_profit_bridge`、`operating_profit_bridge` 和 `ar_cash_impact`。

## D033 Analysis Run 消费边界

- 状态：有效
- 决定：Dashboard、Investigation、AI 和报告共同读取已发布且不可变的 Analysis Run；下游不得重新执行分析公式或修改 Finding 排名。
- 原因：保证所有界面和输出使用同一事实、Driver、证据和策略版本。

## D034 Phase 6 Dashboard 读取边界

- 状态：有效
- 决定：浏览器只通过 typed `GET /api/v1/dashboard/overview` 读取只读投影；该投影只消费相互绑定的已发布 Metric Snapshot、Analysis Run 及治理元数据。
- 禁止：浏览器不得读取原始文件、canonical 事实、Metric Value 或 Analysis 持久化接口，也不得重新计算指标、Driver、Finding 资格和排名。
- 原因：让首个用户界面继承 Phase 1–5 的数字一致性、版本身份和不可变保证。

## D035 Phase 6 Dashboard 桌面信息结构

- 状态：有效
- 决定：桌面端采用深色工作流侧栏、八指标、趋势/经营利润桥/Findings 三栏分析带、产品表/客户群×产品毛利矩阵双栏明细带；页面只保留一个 `h1`。
- 响应式：窄桌面允许 Findings 跨栏、明细转单栏；移动端作为可读复核界面，不以牺牲桌面信息密度为代价。
- 可访问性：滚动表格区域必须可键盘聚焦，表格、矩阵和状态不得只依赖颜色传达含义。

## D036 Investigation 身份交接边界

- 状态：有效
- 决定：Phase 6 的每个 Finding 跳转必须保留 `finding_id`、`batch_id`、`metric_snapshot_id` 和 `analysis_run_id`，并先由不可变身份回执页确认上下文。
- 当前边界：Phase 6 不实现证据下钻和评审；Phase 7 在该身份之上建设 Evidence-first Investigation，不得静默切换批次、快照或运行。
