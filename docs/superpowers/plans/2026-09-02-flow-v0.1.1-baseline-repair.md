# FLOW v0.1.1 Baseline Repair Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Restore one truthful, reproducible FLOW repository and acceptance baseline before building pilot-facing Excel intake and report delivery.

**Architecture:** Keep the application and research archive in the existing `main` history, but make generated knowledge artifacts deterministic and verifiable. Align project-state documents with executable evidence, then add the missing publishing CI gate so every V1 functional boundary has a remote gate. Preserve the seven root user files as untracked duplicates and never rewrite immutable raw archives.

**Tech Stack:** Python 3.13 standard library tests, Git/GitHub Actions, existing Make acceptance gates, Markdown knowledge base, SHA-256 manifests.

## Global Constraints

- Work on the user-authorized single `main` branch; do not create a second long-lived branch.
- Preserve all existing Git history; do not force-push or move `v0.1.0`.
- Do not stage the seven root user files.
- Do not rewrite `01_conversations/raw/`, `02_research/original/`, or original image archives.
- Every behavioral fix follows red-green TDD.
- Regenerate `99_manifest/inventory.tsv` and `sha256sums.txt` after knowledge-base changes.
- Push each completed task to `origin/main`; create `v0.1.1` only after local acceptance and final-HEAD CI are green.
