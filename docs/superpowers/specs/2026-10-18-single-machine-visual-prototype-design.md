# 单机验证原型架构与全视图视觉设计

## 1. 目标与边界

当前产品交付聚焦单机、单用户的财务分析验证原型。系统仍须跑通从公开资料/模拟经营数据接入、客观数据核验、确定性财务计算、驾驶舱分析、来源追溯到报告阅读与导出的真实链路。它不承担本阶段的生产级多租户、复杂角色权限、局域网协作或高可用部署。

用户确认的视觉方向为 A「高管编辑部」+ C「财务报告画布」：驾驶舱呈现精致、沉稳、专业的视觉语言；报告页面以结论、支持图表、来源与口径组成连续阅读路径。高管首页以收入、营业利润、毛利率、经营现金流和行动项为首屏内容。

## 2. 架构决策

### 2.1 运行形态

- 保留当前成熟且已承载完整界面的 Next.js 前端、FastAPI API、Python 财务计算与 ECharts 图表组件；将它们限定在同一台设备、同一位操作者的单机运行边界中。
- 提供一个本机启动入口。启动器只需运行 Web 与 API 两个应用进程；日常运行不要求 Docker、反向代理或外部基础设施服务。
- 停用本阶段不需要的 Redis、Celery Worker、MinIO 与 S3 配置/依赖。用户触发的分析在 API 中同步执行并返回可解释的完成或失败状态；不得用一个永远返回 `accepted` 的队列桩表示业务已完成。
- 保留单用户登录保护和审计身份。多用户目录、角色矩阵和跨企业授权暂缓。

### 2.2 数据与文件存储

- SQLite 单文件是结构化财务事实、指标快照、分析结果、Finding、证据关系、报告版本和审计事件的权威存储。
- 原始输入、报告文件及导出物保存在应用数据目录，沿用内容寻址路径与写入前后 SHA-256 校验；文件与数据库登记记录之间的关系可被校验与恢复。
- Excel 保持为输入/输出交换模板，不直接承担关系型业务状态、指标公式或来源血缘的权威存储。
- 应用数据目录提供单用户备份/恢复包：通过 SQLite 一致性备份接口保存数据库，附带本地文件清单与校验和；恢复后重新核验来源追溯和报告读取。
- 不连接或重置常驻 PostgreSQL、开发/演示数据库。数据库转换、导入与破坏性测试只用一次性隔离数据副本。

### 2.3 迁移原则

- 先比较 ORM 模型、现有 32 个 Alembic revision 与测试夹具，列出 PostgreSQL 专用类型/SQL、默认值、约束、事务语义与 Decimal 精度风险。
- 以 SQLite 作为唯一运行目标，形成一个清楚、版本化、可重复升级的新库初始化/迁移路径。原 PostgreSQL 迁移和 S3 适配历史保留在 Git 中作为旧实现记录，不形成运行时双后端或两套当前 schema 权威源。
- 开发只读/导出式迁移工具，从用户明确指定的 PostgreSQL 导出副本或既有数据包生成新 SQLite 文件；不得自动连接常驻库、自动删除源库或静默丢弃不兼容记录。无法一一转换的记录须列入报告并阻断“迁移成功”结论。
- UUID 和 JSON 字段使用 SQLAlchemy/SQLite 可移植表示；金额在 Python `Decimal` 中计算，禁止依赖 SQLite 浮点聚合承担财务口径。
- 文件存储适配器维持不可变内容寻址接口；导入、财报、报告发布、演示数据装载和导出均使用本地实现，并逐条测试哈希、幂等、缺文件和冲突行为。

## 3. 视觉系统与页面契约

### 3.1 视觉语言

- 主色：墨蓝承载导航与关键结构，暖白/浅纸色承载分析画布，低饱和金色强调主要结论，翡翠绿/砖红表达正向/负向变化；警示与缺失状态使用明确文字、图标及颜色三重编码。
- 通过高质量中文字体层级、网格、留白、数字排版、细致边框、图表标注和报告式标题建立高级感。不把大幅氛围图片、发光渐变、无含义纹理或 3D 当作数据图层。
- 复用 ECharts 6.1、现有图表构建器、表格、筛选、深链和来源抽屉；只有现有能力确实无法表达且已有成熟组件无法适配时才提出新依赖。
- 每个指标始终显示期间、单位、同比/环比基准（具备数据时）、披露/计算/演示类型与来源状态。缺失不补零；图表与其支持数值表保持一致。

### 3.2 分析视图

- **CFO 总览**：四项核心指标、可解释的比较变化、收入/利润/现金流趋势、利润或现金变动桥、行动项和来源说明；一屏形成“结果—趋势—原因线索—需关注事项”的阅读顺序。
- **盈利能力与杜邦**：收入/利润趋势、毛利与费用率、ROE 杜邦三因子、可用时的产品/业务结构贡献；杜邦因子关系和数值可追至指标定义与输入报表行。
- **费用**：费用结构堆叠图、金额/费用率趋势、预算或期间差异排序；差异可下钻到科目、组织、来源记录。
- **资产负债**：资产/负债/权益构成、流动性与杠杆趋势、变化对比；时点余额与期间发生额分开表达。
- **营运资金**：应收、应付、库存、DSO/DPO/DIO/CCC 趋势和构成；只呈现真实存在且可计算的项目。
- **现金流**：经营/投资/筹资现金流组合、期初至期末现金瀑布、利润与经营现金流对照。
- **财务风险**：流动性、偿债和现金风险指标趋势、阈值状态及具体数据缺口说明。
- **集团合并**：已披露分部比较与变化；未披露的抵销信息清楚缺省。
- **数据、分析、报表与指标库**：保留现有上传/批次/质量、分析记录、公式解释、报告输出流程；补齐其与驾驶舱的可达深链，不让图表页面成为孤立终点。

这些是表达目标，不构成新增指标或公开事实。只有输入事实和指标目录能支持时才绘制；页面根据实际覆盖情况显示完整/部分/缺失并解释原因。演示生成值可用于模拟细粒度交互，但明确显示“演示数据”，并与公开披露值、可复算指标、情景值区分。

### 3.3 交互与设备

- 图表点击进入支持明细、指标定义、分析调查或原始报告行；筛选条件与可分享的页面状态保留在 URL。后退/刷新可恢复筛选和深链。
- 关键值无需 hover 才能读取；键盘和触屏可完成筛选、展开来源、选择图表点与打开详情。
- 桌面与手机竖屏是并列设计状态；390 px 窄屏不横向溢出，图表标题、主值、单位、缺失原因和来源在触屏上可读。
- 首屏优先给出可读主图，设置项不占满首屏。图表提供显式值表或等价文本备用，支持打印/截图和报告导出。

## 4. 数据可信与安全不变量

1. 原始公开材料及其摘要、SHA、页表锚点不覆盖；变更生成新版本与审计记录。
2. 披露事实、确定性计算、演示生成数据、情景值在存储、接口和 UI 中分型，不互相冒充。
3. 公式、精度、单位、期间/时点语义和 Decimal 计算规则不因视觉/存储迁移而变化。
4. 每个显示值可追至来源事实或被冻结的快照、公式/定义版本和输入值；缺项不补造。
5. 用户的本地业务目录不被种子、初始化命令或测试重置；备份与恢复单独显式执行。
6. 本阶段仅服务于本机单用户。仍需本地身份保护，不自动开放局域网端口或共享数据目录。

## 5. 实施分期与验收门槛

具体队列和状态只见 [当前路线图](../../50_plans/CURRENT_ROADMAP.md)，工作范围与验收见[实施工作包](../../50_plans/work_items/FLOW--single-machine-visual-prototype.md)。执行顺序：

1. 现状/影响审计：当前全部页面、数据与图表契约、数据库模型/32 次迁移、对象存储调用、任务队列、启动/测试/CI 依赖，归纳不可丢失行为。
2. SQLite 与本地存储隔离验证：核心 ORM 表、decimal 精确度、约束/事务、种子、导入、报表、来源回链、备份恢复端到端；不触碰常驻数据。
3. 收敛存储/运行架构：迁移本地数据接口，形成单一数据库和迁移路径、本机启动器、用户数据目录与备份恢复；移除经验证不需要的 Redis/Celery/MinIO/S3 运行代码和 compose 依赖。
4. 按 A+C 视觉合同逐页完善页面、图表、报表、跨页链接、移动布局和事实/缺失标识；所有图形继续由真实或明确标注的演示数据生成。
5. 全链验收：空库初始化、发行包装载、业务分析、数据下钻、报告/文件恢复、所有页面桌面/手机核验，准确 SHA CI、文档门禁与独立复核。只有准确 SHA 验收通过后才关闭工作包。

**总体验收：** 新用户可按一条本地启动命令打开应用；无 PostgreSQL/Redis/MinIO/Docker 时可以完成指定验证流程；SQLite 与本地文件可备份并完整恢复；主要功能、公式、财务精度和来源追溯无回归；全站视觉与数据事实标记符合本规格，桌面/手机截图可供复核；项目文档、安装说明与唯一计划状态同步。

## 6. 风险与处理

- SQLite 与 32 次 Postgres 迁移并非直接兼容；先做隔离性验证和当前模型/schema 对账。若转换成本或 SQLite 的事务/精度行为使关键功能失真，则不得把降级说成通过，应在本工作包内报告实测边界并优先寻找满足“本机单用户”且运行负担更低的存储路径。
- 内容寻址文件目录失配会使历史报告/证据不可用；文件迁移必须哈希对账，并做跨数据库/文件目录备份恢复演练。
- 同一仓库的主 checkout 有 4 个 2026-10-16 未提交驾驶舱改动（`cockpit.css`、`kpi-card.tsx`、`module-page.tsx`、`cockpit/modules.py`）。本工作区不会覆盖、暂存或合并这些改动；在最终集成前必须核对是否已提交、保留或已由新实现取代。
- 上一全视图任务的最新 CI run `39042517573` 与 `39041228479` 均为 cancelled；旧代码 SHA runs `39040652008`、`39038535194` 为 failure。本工作包不能沿用它们作通过证据，须以本工作包最终 SHA 重新执行完整 CI。
