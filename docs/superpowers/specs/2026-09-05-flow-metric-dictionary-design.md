# FLOW 会计基础数据与财务分析指标库 设计规格

状态：已按 D040 编写，待用户批准后进入实施计划
日期：2026-09-05
决策依据：D040（会计基础数据与财务分析指标库立项，2026-09-05 用户逐项确认）
调研依据：`docs/knowledge-base/02_research/original/07–09` 号资料
配套草案与数据集：`docs/knowledge-base/02_research/synthesis/会计与财务指标知识库_设计草案.md`、`指标库初始数据集_v0_草案.yaml`、`会计基础数据集_v0_草案.yaml`

## 1. 目标

建立两个互相关联的基础数据能力，支撑 D039「准确性优先的财务分析」定位：

1. **会计基础数据**：会计准则登记册、会计科目表（含版本演进）、会计分录模板，做查阅级 + 取数映射；
2. **财务分析指标库**：以指标卡片为单位的数据字典，记录指标定义、结构化公式、口径版本、取数映射、依赖关系、基准与来源。

系统能力要求：**可查询、可更改、可观测、可使用**；并提供**可视化指标库评审台（字典浏览器）**，让每一步建设进展可见。

**分析标准（D041-1）**：财务分析基于客观财务视角，依据会计法规和会计准则；系统以标准「四表一注」（资产负债表、利润表、现金流量表、所有者权益变动表 + 附注）为基准输出物，指标分析建立在报表项目取数之上。

**验证方式（D041-2）**：以真实上市公司财报做**反向解析验证**——选取典型互联网公司/物流公司的年度与季度财报导入系统，系统据此重新生成「四表一注」与完整财经分析报告，再与公司已发布的财报与披露数字逐项比对，以比对结果作为准确性承诺的验证证据。

## 2. 非目标（边界）

- 不做核算级总账（不出凭证、不记账）；核算级留待脱敏试点证据；
- 不修改任何已冻结契约（`flow.excel.v1`、`flow.metrics.logistics.v1` 在迁移完成前继续有效）；
- 不绕过 D016（AI 不创造数字）、D028/D033（不可变快照消费边界）、D031、D037；
- 多租户、角色权限不在本期范围（沿用单用户边界）。

## 3. 对象模型

### 3.1 准则（Standard）

`{id, name, issuer, effective_note, source_ref}`。初始收录与数据集直接相关的 CAS/IFRS 条目（11 条），42 项具体准则全量登记为后续步骤。

### 3.2 会计科目（Account）

`{code, name, category(六大类), balance_side(借/贷/双向/备抵标注), status(current/added_2024/superseded), standard_ref, code_note?}`。

规则：

- 科目体系版本化：2006 附录 156 科目为基线，2024 汇编新增/修订以独立条目叠加，不原地改写；
- 备抵科目（坏账准备、累计折旧等）余额方向显式标注为贷方；
- 企业自定义科目（未来）必须挂接标准科目父级。

### 3.3 分录模板（EntryTemplate）

`{template_id, scenario, business_context, lines:[{direction, account, amount_rule}], standard_ref, related_metrics[], note?}`。

- 每个模板引用科目编号，校验时闭合到科目表；
- `related_metrics` 把分录场景链接到指标库，形成「业务 → 分录 → 科目 → 指标」的取数映射链；
- 初始收录物流供应链业务 17 个典型场景。

### 3.4 指标卡片（MetricCard）

`{metric_code, name, aliases, domain(能力域), definition, formula_text, formula(结构化 AST), unit, time_behavior, caliber(口径版本说明), source_cas, source_ifrs, depends_on[], benchmark, mpm, reconciliation?, provenance, status}`。

关键规则：

- **口径并存**：同一指标的多口径（如 ROE 平均/期末、DSO 360/T12）以口径版本记录，不强制唯一公式；
- **MPM 标识**：管理层自定义指标（EBITDA、调整后 EBITDA、FCF、管理口径利润等）必须给出与法定口径的调节关系（IFRS 18 / KPMG 披露要求）；
- **显式依赖边**：depends_on 闭合于库内指标，构成可遍历的指标依赖图；
- **来源可溯**：provenance 指向研究档案或工程契约。

### 3.5 勾稽关系（Relation）

指标间计算依赖之外的组合关系（杜邦三分解、净营业周期、交叉验证规则），供分析 playbook 与 Copilot 引用。

### 3.6 报表项目（StatementLineItem，D041 新增）

`{item_id, statement(资产负债表/利润表/现金流量表/所有者权益变动表/附注), name, cas_ref, ifrs_ref, account_mapping[], note?}`。

- 「四表一注」（资产负债表、利润表、现金流量表、所有者权益变动表 + 附注）是依据会计准则的**标准输出物**；分析必须基于客观财务视角，依照会计法规和会计准则；
- 报表项目到科目的映射（account_mapping）把取数链补全为「业务 → 分录 → 科目 → 报表项目 → 指标」；v0 数据集已含 28 个 CAS↔IFRS 报表项目对照，作为本对象的初始内容；
- 附注（Notes）本期定位为**披露项目清单 + 取数标注**（哪些附注信息是指标口径必需的，如账龄、分部、租赁明细），不做全文生成。

## 5. 四项系统能力设计

| 能力 | 本期（字典阶段） | 产品化阶段 |
|---|---|---|
| 可查询 | YAML 数据集 + 可视化浏览器的搜索/筛选 | 检索 API + Web 字典页 + Copilot 自然语言查口径 |
| 可更改 | 数据集修订 = 新版本文件 + 变更记录；不原地覆盖 | 版本化变更流程（草案→生效→废止）+ 审计 |
| 可观测 | 浏览器顶部统计（科目/指标/分录/关系数量）随每次重建更新，进展可见 | 指标使用方清单、变更影响提示 |
| 可使用 | 指标公式为结构化 AST，可被引擎消费 | 指标库成为引擎/驾驶舱/报告/Copilot 唯一口径来源 |

## 6. 可视化方案（用户明确要求）

**指标库评审台（字典浏览器归并后的唯一可视化产物）**：自包含 HTML 页面，由 `scripts/generate_metric_library_review.py` 从两个 YAML 数据集机械生成，输出 `docs/knowledge-base/03_assets/visual_prototypes/metric-library-v0-review.html`，每一次数据演进后重建，作为「每一步进展」的可视化窗口：

- 生成时间戳：页面头部显示本次重建时间，便于确认数据新鲜度；
- 总览统计带：科目数、指标数、分录模板数、勾稽关系数、MPM 数（即建设进度）；
- 指标评审视图：按能力域/层级分组、关键词搜索、**仅看 MPM** 过滤；指标卡片展示公式、口径、依赖、基准、来源；支持逐项 **纳入/待定/剔除** 评审并持久化（localStorage），底部 dock 汇总评审统计并可复制筛选结果；
- 杜邦依赖树：核心盈利指标的勾稽关系可视化；
- CAS↔IFRS 映射页 + 42 项具体准则清单；
- 会计基础页：科目（六大类分组、搜索、余额方向与状态标注）、准则登记册、分录模板（场景、借贷结构、关联指标）与已知缺口；
- 不依赖任何外部资源（无 CDN、无构建），双击即可打开。

产品化阶段，该评审台演进为 FLOW Web 内的 `/dictionary` 页面，数据源由 YAML 切换为数据库对象；评审结论（纳入/剔除）将进入指标库版本化变更流程。

## 7. 与现有架构的衔接

- `flow.metrics.logistics.v1`（代码内 15 指标、14 依赖边）在指标库产品化后迁移为库内「物流行业指标集」版本；迁移前现有引擎、门禁、快照行为不变；
- 会计科目层是新增底座，为「科目余额表 → 指标取数」通道预留映射（本期只建映射，不建核算）；
- 指标库 YAML 草案成熟后，按契约治理流程转为 `config/` 下的工程契约并配 CI 门禁。

## 8. 分期与验收

- **P1（本轮）**：两个 v0 数据集 + 指标库评审台（字典浏览器）+ 规格；验收 = YAML 结构校验通过、评审台渲染验证、索引与清单更新；
- **P2**：补齐 2024 汇编全量科目、42 项准则登记册；分录模板扩展；用户评审口径质量；
- **P3**：指标库数据库对象与版本化变更流程；字典 Web 页面；报表项目（四表一注）对象落库并接通科目映射；
- **P4**：迁移 `flow.metrics.logistics.v1` 为库内指标集，引擎改从库读取，配门禁；
- **P5（验证实验，D041-2）**：真实财报反向解析验证（见第 10 节），与 P3/P4 并行准备样本；
- P3/P4 与 Pilot Phase 2 及脱敏试点并行（D040-5），真实试点证据优先决定 V1.1 范围的约束不变。

## 10. 验证实验设计：真实财报反向解析（D041-2）

目的：用可公开复核的真实证据检验「准确性承诺」——系统能否从原始财报数据出发，重建准则口径的「四表一注」与财经分析报告，并与公司已发布结果一致。

### 10.1 样本选择

- 候选清单与逐项可得性核查已完成（2026-09-05），见 `docs/knowledge-base/02_research/original/11_验证样本财报可得性调研_资料.md`；建议首批 **顺丰控股（002352.SZ，CAS）+ 腾讯控股（0700.HK，IFRS + Non-IFRS 调节表）+ 京东物流（2618.HK，IFRS，物流分部）**，XBRL 管道样本从中通（ZTO）/阿里（BABA）二选一（注意两者 SEC 口径为 US GAAP，启用前核实港股版本准则口径）；
- 每家公司取**当年度 + 当季度**财报；完整季度级四表重建仅 A 股季报（顺丰）可支持，港股以年度 + 中期 + 季度业绩公告为准；
- 覆盖 CAS（A 股）与 IFRS（港股）两种准则口径，兼作 CAS↔IFRS 对照数据的实测（顺丰季报声明 CAS 与 IFRS 无差异，提供一致性参照）。

### 10.2 流程

1. **导入**：获取公司发布的财报原文（PDF / XBRL），抽取报表项目数值与附注明细；
2. **反向解析**：系统按科目映射与指标库口径，重建四表一注（本期：四表数值重建 + 附注取数标注）；
3. **报告生成**：基于重建的报表项目运行指标库，生成完整财经分析报告；
4. **逐项比对**：系统输出与公司已发布财报、披露的管理层讨论逐项 diff；差异分级为——口径差异（多口径并存，须标注）、解析误差（系统缺陷，进入修复）、披露缺失（原文无可得数据，诚实标注）。

### 10.3 验收标准

- 四表关键行项目（资产总计、负债合计、收入、净利润、经营现金流等）与发布值**一致或差异可归因到明确口径**；
- 指标库计算结果与公司披露的同口径指标（如有）一致；
- 全部差异留痕：比对表作为验证证据归档，可追溯、可复核（符合 D016/D028/D031 边界）。

### 10.4 与既有边界的关系

- 本实验是**验证手段**，不替代 Pilot Phase 2 的脱敏真实数据试点；两者证据合并后优先决定 V1.1 范围；
- 实验仅使用公司公开发布的财报，不涉及任何非公开数据。
