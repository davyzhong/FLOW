## 1. 目标

建立两个互相关联的基础数据能力，支撑 D039「准确性优先的财务分析」定位：

1. **会计基础数据**：会计准则登记册、会计科目表（含版本演进）、会计分录模板，做查阅级 + 取数映射；
2. **财务分析指标库**：以指标卡片为单位的数据字典，记录指标定义、结构化公式、口径版本、取数映射、依赖关系、基准与来源。

系统能力要求：**可查询、可更改、可观测、可使用**；并提供**可视化字典浏览器**，让每一步建设进展可见。

## 2. 非目标（边界）

- 不做核算级总账（不出凭证、不记账）；核算级留待脱敏试点证据；
- 不修改任何已冻结契约（`flow.excel.v1`、`flow.metrics.logistics.v1` 在迁移完成前继续有效）；
- 不绕过 D016（AI 不创造数字）、D028/D033（不可变快照消费边界）、D031、D037；
- 多租户、角色权限不在本期范围（沿用单用户边界）。

## 3. 对象模型

### 3.1 准则（Standard）

`{id, name, issuer, effective_note, source_ref}`。初始收录与数据集直接相关的 CAS/IFRS 条目（11 条），42 项具体准则全量登记为后续步骤。

### 3.2 会计科目（Account）

`{code, name, category(六大类), balance_side(借/贷/双向/备抵标注), status(current/added_2024/superseded), standard_ref, code_note?}`。

规则：

- 科目体系版本化：2006 附录 156 科目为基线，2024 汇编新增/修订以独立条目叠加，不原地改写；
- 备抵科目（坏账准备、累计折旧等）余额方向显式标注为贷方；
- 企业自定义科目（未来）必须挂接标准科目父级。

### 3.3 分录模板（EntryTemplate）

`{template_id, scenario, business_context, lines:[{direction, account, amount_rule}], standard_ref, related_metrics[], note?}`。

- 每个模板引用科目编号，校验时闭合到科目表；
- `related_metrics` 把分录场景链接到指标库，形成「业务 → 分录 → 科目 → 指标」的取数映射链；
- 初始收录物流供应链业务 17 个典型场景。

### 3.4 指标卡片（MetricCard）

`{metric_code, name, aliases, domain(能力域), definition, formula_text, formula(结构化 AST), unit, time_behavior, caliber(口径版本说明), source_cas, source_ifrs, depends_on[], benchmark, mpm, reconciliation?, provenance, status}`。

关键规则：

- **口径并存**：同一指标的多口径（如 ROE 平均/期末、DSO 360/T12）以口径版本记录，不强制唯一公式；
- **MPM 标识**：管理层自定义指标（EBITDA、调整后 EBITDA、FCF、管理口径利润等）必须给出与法定口径的调节关系（IFRS 18 / KPMG 披露要求）；
- **显式依赖边**：depends_on 闭合于库内指标，构成可遍历的指标依赖图；
- **来源可溯**：provenance 指向研究档案或工程契约。

### 3.5 勾稽关系（Relation）

指标间计算依赖之外的组合关系（杜邦三分解、净营业周期、交叉验证规则），供分析 playbook 与 Copilot 引用。

| 数据集 | 文件 | 规模 |

## 5. 四项系统能力设计

| 能力 | 本期（字典阶段） | 产品化阶段 |
|---|---|---|
| 可查询 | YAML 数据集 + 可视化浏览器的搜索/筛选 | 检索 API + Web 字典页 + Copilot 自然语言查口径 |
| 可更改 | 数据集修订 = 新版本文件 + 变更记录；不原地覆盖 | 版本化变更流程（草案→生效→废止）+ 审计 |
| 可观测 | 浏览器顶部统计（科目/指标/分录/关系数量）随每次重建更新，进展可见 | 指标使用方清单、变更影响提示 |
| 可使用 | 指标公式为结构化 AST，可被引擎消费 | 指标库成为引擎/驾驶舱/报告/Copilot 唯一口径来源 |

## 6. 可视化方案（用户明确要求）

**字典浏览器**：自包含 HTML 页面，由 `scripts/build_dictionary_viewer.py` 从两个 YAML 数据集机械生成，每一次数据演进后重建，作为「每一步进展」的可视化窗口：

- 顶部统计带：科目数、指标数、分录模板数、勾稽关系数、MPM 数（即建设进度）；
- 指标视图：按能力域分组浏览、关键词搜索、MPM 过滤；指标卡片展示公式、口径、依赖、基准、来源；
- 科目视图：按六大类分组、搜索、余额方向与状态标注；
- 分录视图：场景列表、借贷结构、关联指标；
- 不依赖任何外部资源（无 CDN、无构建），双击即可打开。

产品化阶段，该浏览器演进为 FLOW Web 内的 `/dictionary` 页面，数据源由 YAML 切换为数据库对象。

## 7. 与现有架构的衔接

- `flow.metrics.logistics.v1`（代码内 15 指标、14 依赖边）在指标库产品化后迁移为库内「物流行业指标集」版本；迁移前现有引擎、门禁、快照行为不变；
- 会计科目层是新增底座，为「科目余额表 → 指标取数」通道预留映射（本期只建映射，不建核算）；
- 指标库 YAML 草案成熟后，按契约治理流程转为 `config/` 下的工程契约并配 CI 门禁。

## 8. 分期与验收

- **P1（本轮）**：两个 v0 数据集 + 字典浏览器 + 规格；验收 = YAML 结构校验通过、浏览器渲染验证、索引与清单更新；
- **P2**：补齐 2024 汇编全量科目、42 项准则登记册；分录模板扩展；用户评审口径质量；
- **P3**：指标库数据库对象与版本化变更流程；字典 Web 页面；
- **P4**：迁移 `flow.metrics.logistics.v1` 为库内指标集，引擎改从库读取，配门禁；
- P3/P4 与 Pilot Phase 2 及脱敏试点并行（D040-5），真实试点证据优先决定 V1.1 范围的约束不变。

## 9. 未决事项

- 2024 汇编原文获取渠道（购买/图书馆/官方出版物）；
- 字典浏览器是否需要随每次推送自动重建（CI 钩子）——建议 P2 决定；
- 指标基准值的行业数据来源（评级报告已覆盖部分，行业基准库属长期建设）。
