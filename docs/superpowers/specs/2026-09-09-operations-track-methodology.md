# 经营分析轨方法论规格 v1（OP 方法论）

- 日期：2026-09-09；决策依据：[D050](../../knowledge-base/04_decisions/DECISION_LOG.md)（采纳自外部 SOP 资料的分析判断）、D045（双轨结构）、D046（经营轨数据定义由知识库提炼）、D047（默认推荐策略）、D049（客观基础优先）
- 来源：[《终于有人把经营分析给说清楚了！》分析判断](../../knowledge-base/02_research/synthesis/2026-09-09-operations-sop-assessment.md)（原始档案同日归档）；参照数据熊 04_经营分析合集（Obsidian 知识库）
- 性质：经营轨（`/operations` 双轨第二轨）的搭建方法论与数据定义合同。财务轨优先级不变（D046 步骤 1）；本规格只约束经营轨，不改动财务轨既有合同。

## OP-0 数据可得性分层（第一原则）

每个经营轨主题、指标、分析条目必须携带 `availability` 标注；**数据层不可得的分析不生成数值，只注册占位并返回 `not_applicable`（附 typed 原因）**，沿用「缺失不等于零、缺失不补造」。

| 层 | 名称 | 数据源 | 当前状态 |
|---|---|---|---|
| L1 | 结果层 | 公开财报（利润表/资产负债表/现金流量表/分部报告） | **可建**——财务轨标准事实直接复用 |
| L2 | 过程层 | 内部运营数据（量价、订单流、转化漏斗、周转过程） | 注册占位；内部数据授权后启用（U9/试点） |
| L3 | 事件层 | 业务事件簿（活动/新品/渠道投放等增量投入台账） | 注册占位；表结构随 v1 定义，数据待授权 |
| L4 | 行动层 | 方案制定与验证（五环闭环后两环） | 后置（D049：行动闭环不在当前实施范围） |

## OP-1 指标体系三层

沿用 SOP 分层并挂接数据可得性；全部指标走 FLOW 指标治理（库内版本化、口径标签必带、未注册口径拒绝）：

- **结果指标**（L1 可建）：收入、毛利、经营利润、净利润、经营现金流净额及同比/趋势——与财务轨共用标准事实与 formula_ref，不另算一套数字。
- **过程指标**（仅 L2+）：转化率、客单价、复购率、周转过程量——财报期 `not_applicable`。
- **行为指标**（仅 L2+）：访问量、加购数、支付单数——同上。

## OP-2 拆解纪律（复用 U2 原语，不自建计算内核）

- **加法桥**（收入结构、成本费用结构、利润变动桥）：用 C08 可加和守恒桥——分项之和必须还原总变化额，残差显式展示，禁止静默凑整。
- **乘法链**（量价桥、漏斗）：仅在显式数量×单价数据存在时生成（铁律）；财报期一律不生成。
- **联动与阈值**：增速联看用 I09 模式（仅提示复核，不断言原因）；经验阈值用 C06 模式（scope-labeled hint，无普适判定）；口径引用用 I12 模式（登记制标签）。
- **CAGR/趋势**：C07 契约（n−1 间隔）。
- 数学分解（含杜邦）一律标注「数学恒等，不解释为业务因果」。

## OP-3 分析主题六板块（看板内容合同）

SOP 六板块经数据可得性适配后的经营轨默认主题：

| 板块 | 内容 | availability |
|---|---|---|
| 增长质量 | 营收趋势/同比/增速；良性增长信号中可客观化部分（投产比趋势仅 L3） | L1（+L3 增强） |
| 收入结构 | 分部/产品线/区域收入占比与变动（财报分部报告） | L1 |
| 成本费用结构 | 成本结构桥、费用率结构、经营利润桥 | L1 |
| 盈利质量 | 杜邦三分解（带完整口径标注）、净现比（利润现金含量） | L1 |
| 用户与渠道 | 用户分级、渠道 CAC/LTV、获客结构 | 仅 L2/L3 |
| 运营效率 | 资产/存货/应收周转类 | L1（可算部分） |

## OP-4 看板信息架构（/operations 页面）

1. 先总体后细分；核心指标在前、解释指标在后。
2. 顶部总体结果指标卡 → 板块下钻 → 每个数字可溯源（事实链：值、比较基准、口径、来源引用）。
3. `not_applicable` 的 L2/L3 板块以「待内部数据」状态展示注册框架，不隐藏、不伪造数据。

## OP-5 闭环与事件模型

- **业务事件簿**为一等公民数据模型（L3）：事件类型（营销活动/新品上市/渠道变更/价格调整）、期间、增量投入额、覆盖范围、效益评估字段；常规投入与增量投入分账，考核规则去重检查。
- **五环闭环**：目标监控、经营诊断 → 映射 Investigation/Finding 既有状态机（事实/判断/问题/建议四要素结论）；原因定位输出「关联信号」（I09 模式）；方案制定、方案验证 → L4 后置。

## OP-6 报告与发布

经营轨分析输出走财务轨同一发布链：指标快照 → 分析条目计算 → 冻结 Report Snapshot（JSONB 不可变）→ 发布尝试与下载校验。不建 BI 导出旁路；经营轨报告资格与客观报告门禁（U5/U6）对齐后接入。

## 落地阶段（详见[经营轨执行计划](../plans/2026-09-09-operations-track-plan.md)）

O1 数据定义合同与注册表（本规格 + `operations_track_v1.yaml`）→ O2 L1 指标计算接线 → O3 分析条目与六主题报告 → O4 `/operations` 看板改版 → O5 L2/L3 内部数据接入（依赖授权）。每阶段 TDD、提交推送、CI 绿才算 done；与 U 系列并行领取，不阻塞财务轨主线（D046）。
