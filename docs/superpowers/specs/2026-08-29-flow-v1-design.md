## 1. 产品定义

FLOW V1 是一个面向物流供应链企业 Finance BP 的 AI 经营分析工作台。它把分散的 Excel 数据转换为可信、可诊断、可复核、可发布的经营分析结果，完整覆盖一次月度经营分析的主要工作链路：

```text
导入数据
→ 标准化与对账
→ 经营监控
→ 异常识别
→ 结构化调查
→ 证据复核
→ Finance BP 签发结论
→ PPT / Excel / 正式月报发布
```

V1 的核心价值不是展示更多图表，而是让 Finance BP 能够回答并证明以下问题：

1. 本月和年度累计的经营结果如何？
2. 与预算和上年同期相比，差距在哪里？
3. 规模增长是否带来收入、利润和现金增长？
4. 利润或现金缺口由哪些经营驱动造成？
5. 分析结论依赖哪些数据、公式和业务证据？
6. 同一结论如何一致地发布到驾驶舱、PPT、Excel 和正式月报？

## 2. 用户与使用场景

### 2.1 首要用户

V1 只设计 Finance BP 主视角，不提供管理层专属视图或角色切换。

Finance BP 在系统中承担三种职责：

- 数据准备者：导入、映射、校验并确认本期分析数据；
- 分析者：识别异常、拆解驱动、核验证据并形成判断；
- 发布者：审阅并签发经营分析 PPT、分析 Excel 和正式月报。

### 2.2 首版业务场景

V1 聚焦物流企业的供应链业务月度经营分析，采用客户群与物流产品双核心维度：

- 客户群：战略客户、市场化客户；
- 物流产品：仓配一体、运输配送、跨境供应链、大件、快消供应链、美妆健康、进口供应链、M2C/城市配送；
- 辅助维度：月份、组织、区域、客户、管理科目，扩展后支持仓库、线路、承运商、成本中心和项目。

首版内置一个高度拟真的 12 个月模拟数据集和年度月度预算。模拟经营故事为：

- 订单和收入增长；
- 增长更多来自低毛利业务；
- 运输和外包履约成本上升；
- 战略客户账期延长；
- 毛利率下降、经营利润低于预算、经营现金流恶化。

## 3. V1 范围

### 3.1 包含

- 模块化 FLOW 标准 Excel 数据包；
- 单个多工作表 Excel 分析批次；
- 外部非标准 Excel 的 AI 识别、字段映射和标准模板转换；
- 数据清洗、质量检查、关系校验、业务校验和财务对账；
- 数据库标准数据中间层；
- 指标定义、计算、快照和版本；
- Finance BP 高信息密度经营驾驶舱；
- 独立 Investigation Workspace；
- 公式、数据血缘、源记录、证据和人工复核；
- 有明确边界的 AI 解读、追问和内容编排；
- PPT、分析 Excel、HTML/PDF 正式月报；
- 分析批次、计算版本、Finding 状态和发布版本留痕。

### 3.2 不包含

- 实时或日度经营监控；
- 多滚动预测版本和完整预测工作流；
- 管理层专属驾驶舱；
- 复杂企业权限和组织隔离体系；
- 问题派单、责任人、截止日期和整改闭环；
- 任意行业和任意复杂 Excel 的无限适配；
- 将 Excel 文件作为系统内部数据库；
- Word 格式正式月报。V1 的正式月报格式为 HTML/PDF，Word 作为后续扩展。

## 4. 核心设计原则

1. **标准层唯一依赖**：所有下游功能只能读取标准数据中间层和指标语义层，禁止直接读取原始文件。
2. **原始数据不可变**：原始文件和原始值永久保留，清洗和转换产生新版本，不覆盖来源。
3. **一次转换，多处复用**：同一标准数据和计算结果服务驾驶舱、Investigation、AI 和全部报告。
4. **计算先于解释**：差异、驱动和影响金额由确定性计算引擎产生，AI 不自行创造数字。
5. **事实、判断和假设分离**：未经验证的推断必须标记为假设。
6. **证据决定发布资格**：关键证据未完成复核的 Finding 不得进入正式报告。
7. **全程可追溯**：报告数字必须能够反向追溯到指标公式、标准表记录、转换规则和 Excel 源行。
8. **部署方式中立**：V1 架构不绑定纯本地模式，可部署为 Web 应用、私有部署或其他应用形态。

## 5. 总体系统架构

FLOW V1 划分为七个职责明确的能力模块：

| 模块 | 职责 | 主要输入 | 主要输出 |
|---|---|---|---|
| Data Intake | 模板生成、文件上传、工作表识别、字段映射 | Excel 文件、模板配置 | 映射方案、标准化候选数据 |
| Canonical Data | 批次、标准事实表、维度、质量、血缘 | 转换后的标准记录 | 可发布分析批次 |
| Metric Engine | 指标定义、公式、维度、目标、阈值、版本 | 标准事实表和维度表 | Metric Snapshot |
| Analysis Engine | 差异、趋势、驱动、维度下钻和影响测算 | Metric Snapshot、标准明细 | Finding 候选、Driver Contribution |
| Investigation | 证据核验、结论编辑、审阅和签发 | Finding 候选、驱动和源记录 | 已批准 Finding |
| AI Copilot | 解释、追问、叙事和报告编排 | 已计算指标、Finding、证据 | 带引用的文本草稿和编排建议 |
| Publishing | 多格式渲染、版本冻结和发布记录 | 已批准分析对象和报告模板 | PPTX、XLSX、HTML/PDF |

模块之间通过稳定对象和版本化接口连接。任何模块的内部实现可以替换，但不得绕过标准数据层或破坏对象契约。

## 6. 数据架构

### 6.1 五层数据流

```text
外部数据源
→ 原始保留区
→ 接入、映射、清洗、校验与对账
→ FLOW 标准数据中间层
→ 指标语义与分析层
→ 驾驶舱、Investigation、AI 和发布层
```

外部数据源可以是非标准 Excel、FLOW 标准模板、未来的 ERP/财务系统、业务系统或 API。所有来源最终都转换为相同的数据库标准表。

### 6.2 原始保留区

每次上传创建不可变的 Source File 记录，至少保存：

- 原始文件；
- 文件名、大小和文件指纹；
- 上传时间和分析批次；
- 工作表结构、原始表头和原始值；
- 使用的映射方案和转换规则版本；
- 导入错误、警告和人工确认记录。

### 6.3 标准事实表

| 标准表 | 推荐粒度 | 核心内容 |
|---|---|---|
| `fact_operating_actual` | 月 × 组织 × 客户 × 物流产品 × 区域 | 订单、件量、收入、仓储/运输/其他直接成本 |
| `fact_financial_actual` | 月 × 组织 × 管理科目 | 收入、成本、费用、利润、经营现金流 |
| `fact_budget` | 月 × 组织 × 客户群 × 物流产品 × 指标/管理科目 | 经营量、收入、成本、利润和现金预算 |
| `fact_ar_collection` | 月 × 客户 × 发票或账龄段 | 应收余额、到期、逾期、回款和信用账期 |

### 6.4 共用维度表

- `dim_period`：月份、季度、年度和 YTD 标识；
- `dim_organization`：集团、业务单元、利润中心；
- `dim_customer`：客户 ID、名称、行业、等级和账期；
- `dim_customer_segment`：战略客户、市场化客户；
- `dim_logistics_product`：物流产品和产品层级；
- `dim_region`：大区、省份、城市；
- `dim_management_account`：财务科目到管理口径的映射；
- `dim_scenario_version`：实际、预算及未来扩展的预测/情景版本。

### 6.5 扩展事实和维度

财务管理扩展：

- 费用明细；
- 成本中心；
- 项目和专项投入；
- 现金流项目；
- 计划版本。

物流运营扩展：

- 订单履约明细；
- 仓库和作业；
- 线路和运输方式；
- 承运商结算；
- 服务质量、异常和赔付。

扩展模块不得改变核心事实表结构。它们通过期间、组织、客户、产品、区域、成本中心等稳定 ID 与核心数据关联。

## 7. FLOW 标准 Excel 数据包

### 7.1 定位

标准 Excel 数据包是标准数据契约的外部表达形式，不是系统内部数据库。它同时支持两种路径：

1. 用户或外部人员直接按照模板填写；
2. 系统将非标准 Excel 识别并转换为标准模板结构，供用户核对。

### 7.2 模块化单工作簿

每个分析批次使用一个多工作表 Excel 文件。用户选择分析场景后，系统从统一契约生成所需工作表。

核心必需工作表：

- `00_填写说明`
- `01_分析批次`
- `02_经营实际`
- `03_财务实际`
- `04_月度预算`
- `05_应收回款`
- `06_客户主数据`
- `07_物流产品`
- `08_组织与区域`
- `09_管理科目`

财务扩展工作表：

- `20_费用明细`
- `21_成本中心与项目`
- `22_现金流项目`
- `23_计划版本`

物流扩展工作表：

- `30_订单履约明细`
- `31_仓库与作业`
- `32_线路与运输`
- `33_承运商结算`
- `34_服务质量`

### 7.3 模板规则

- 模板包含明确版本号；
- 每个字段具有稳定字段 ID、显示名称、类型、单位、必填状态和业务说明；
- 用户可以调整列顺序和允许修改的显示名称，但不能修改标准字段 ID；
- 核心表使用稳定 ID 关联，不依赖工作表行号或列位置；
- 必填数据缺失、主键重复或关系断裂属于阻断错误；
- 异常负值、零订单有收入、单位疑似错误等属于需要人工确认的警告；
- 经营收入和成本必须与财务实际在配置阈值内完成对账。

## 8. 数据接入与质量工作流

导入采用五步流程：

1. 上传单个多工作表 Excel；
2. 识别工作表角色、表头、数据区域、字段类型和粒度；
3. AI 建议源字段到标准字段的映射，用户确认低置信度和业务口径；
4. 应用版本化清洗规则并执行结构、关系和业务校验；
5. 完成经营/财务对账，发布为不可变的正式分析批次。

每个处理动作都必须记录：原值、新值、规则、执行时间、执行主体和原因。失败批次可以修改映射或规则后重新生成新版本，不能覆盖已发布版本。

## 9. 指标语义与分析引擎

### 9.1 指标对象

Metric Definition 至少包含：

- 稳定指标 ID；
- 名称和业务定义；
- 公式和依赖字段；
- 适用维度和聚合方式；
- 单位和格式；
- 实际、预算、同比和 YTD 比较规则；
- 目标和预警阈值；
- 生效期间和版本。

每次发布分析批次时生成 Metric Snapshot。所有页面和报告引用 Snapshot，而不是各自重复计算。

### 9.2 首版指标链

```text
订单量 / 履约件量
→ 收入与业务结构
→ 单均收入 / 单均成本
→ 毛利与经营利润
→ 应收、回款和 DSO
→ 经营现金流与现金转换
```

### 9.3 分析能力

- 当月、YTD、预算、同比和近 12 个月趋势；
- 客户群 × 物流产品交叉分析；
- 组织、区域、客户和管理科目下钻；
- 收入的 Volume / Price / Mix 分解；
- 毛利和经营利润差异桥；
- 履约成本的费率、业务量和效率分解；
- 应收、账龄、DSO、回款和现金影响分析；
- 按财务影响、持续性、证据完整度和管理相关性排序异常。

## 10. Finding、证据与 Investigation

### 10.1 核心对象

- **Finding**：异常事实、财务影响、业务含义、状态和置信度；
- **Driver Contribution**：原因类别、计算方法、贡献金额和贡献比例；
- **Evidence**：计算结果、源记录、业务文件或人工确认；
- **Review**：复核人、意见、状态和时间；
- **Conclusion**：已验证事实、分析判断、待确认事项和建议。

### 10.2 Investigation 流程

```text
确认异常
→ 量化财务影响
→ 分析驱动因素
→ 多维下钻
→ 核验证据
→ 形成 Finance BP 结论
→ 签发或退回
```

Investigation 页面必须同时提供：

- 异常定义和影响金额；
- 驱动桥和贡献排序；
- 客户、产品、区域等维度下钻；
- 指标公式和计算引擎版本；
- 数据质量和对账结果；
- 从标准记录到 Excel 源行的数据血缘；
- 证据状态和审阅记录；
- 结构化结论编辑区；
- 右侧上下文感知的 AI 分析助手。

证据状态至少包括：待验证、已验证、被否定。关键证据未验证时，Finding 不具备正式发布资格。

## 11. 页面信息架构

左侧主导航按照 Finance BP 工作流组织：

### 本期工作

- 数据导入
- 数据质量
- 经营驾驶舱
- 分析调查

### 分析专题

- 规模与收入
- 盈利与成本
- 应收与现金

### 管理与交付

- 指标与口径
- 洞察与结论
- 报告中心
- 分析批次与发布记录

### 11.1 经营驾驶舱

驾驶舱采用“总览 + 异常 + 专题下钻”的高信息密度布局：

- 顶部全局筛选：期间、当月/YTD、组织、客户群、物流产品、区域；
- 数据状态：批次、更新时间、数据质量和对账状态；
- 核心指标：订单、收入、单均收入、毛利率、履约成本率、经营利润、应收、经营现金流；
- 每个指标同时显示预算差、同比和 YTD 预算差；
- 近 12 个月规模、收入、盈利和现金趋势；
- 经营利润或毛利差异桥；
- 按财务影响排序的 Findings；
- 物流产品经营明细表；
- 客户群 × 物流产品表现矩阵；
- AI 分析摘要和 Investigation 入口。

视觉方向吸收企业财务驾驶舱的蓝白风格、全局筛选、指标矩阵、风险区域和结论栏，同时保留 FLOW 的高密度明细、异常影响和证据入口。

## 12. AI 能力与边界

AI 可以：

- 识别工作表、表头、字段类型和候选映射；
- 解释映射理由和数据质量异常；
- 基于确定性计算结果归纳 Finding；
- 在 Investigation 中回答基于当前批次的问题；
- 将已批准指标、Finding 和证据组织成报告叙事；
- 推荐需要进一步确认的业务问题。

AI 不可以：

- 自行修改原始数据；
- 在没有记录的情况下替用户确认业务口径；
- 自行计算或编造财务数字；
- 将假设描述为已验证事实；
- 绕过证据状态签发 Finding；
- 在未锁定数据和指标版本的情况下发布正式报告。

AI 输出必须引用其依赖的指标、Finding 或 Evidence ID。无法验证的内容必须明确标记为假设或数据不足。

## 13. 统一发布架构

发布层使用一次分析、多端渲染的方式：

```text
Metric Snapshot + Charts + 已批准 Findings + Evidence
→ AI 内容编排器
→ 人工审阅与签发
→ PPT / 分析 Excel / HTML-PDF 月报
```

AI 内容编排器负责选择重点、排序、生成标题、执行摘要、章节叙事和图表说明，不重新计算数据。

### 13.1 PPT

- 面向汇报、讨论和决策；
- 采用结论先行结构；
- 包含经营概览、规模收入、盈利成本、应收现金和重点建议；
- 附录提供指标口径和证据索引。

### 13.2 分析 Excel

- 面向核查、穿透和二次分析；
- 包含指标结果、差异、趋势、驱动明细和可筛选底表；
- 包含指标口径、数据质量和源记录索引。

### 13.3 正式月报

- V1 输出 HTML 和 PDF；
- 提供结构化正文、图表、指标与证据脚注；
- 记录报告版本、数据批次、指标版本、审阅和签发信息。

## 14. 错误处理与恢复

### 14.1 阻断错误

以下情况禁止发布分析批次：

- 文件无法解析或模板版本不支持；
- 必需工作表或字段缺失；
- 主键重复；
- 必需维度关联失败；
- 经营与财务对账差异超过允许阈值；
- 指标计算依赖缺失。

系统必须给出工作表、字段、记录和修复建议。用户修复后创建新导入版本。

### 14.2 可确认警告

以下情况允许用户说明原因后继续：

- 低置信度字段映射；
- 异常负值或零值；
- 单位、币种或含税口径疑似不一致；
- 可选维度无法匹配；
- 扩展表缺失导致的分析深度下降。

确认记录必须进入审计轨迹。

### 14.3 分析降级

当缺少支持某项诊断的数据时，系统只展示可验证的描述或对比分析，并明确说明无法完成的驱动分析。AI 不得补全缺失事实。

### 14.4 发布恢复

发布失败不改变已批准分析对象。格式渲染器可以针对同一不可变 Report Snapshot 重试，避免重算造成数字变化。

## 15. 验证与测试策略

### 15.1 数据模板与接入

- 标准模板往返测试：生成、填写、导入后字段和数值不丢失；
- 非标准 Excel 映射测试：已知样例能转换到标准字段；
- 结构错误测试：缺表、缺列、重复主键和类型错误被准确定位；
- 清洗留痕测试：每次值变化都能还原原值、规则和版本；
- 财务对账测试：通过和失败案例均符合阈值规则。

### 15.2 指标和分析

- 关键指标使用独立已知答案数据集进行单元验证；
- 当月、YTD、同比和预算比较覆盖边界月份；
- Volume / Price / Mix、利润桥和现金影响满足加总恒等式；
- 不同维度聚合结果与总计一致；
- 驾驶舱、Investigation 和报告引用同一 Metric Snapshot。

### 15.3 Finding 与证据

- 每个 Finding 的影响金额可以重新计算；
- 每条关键证据能够追溯到标准记录和源文件位置；
- 待验证或被否定的关键证据阻止 Finding 发布；
- 人工复核和退回操作形成完整审阅记录。

### 15.4 AI

- AI 回答只能引用当前分析批次和允许的分析对象；
- 数字引用与确定性计算结果一致；
- 数据不足时正确降级并标记假设；
- 未批准 Finding 不会被正式报告编排器选用；
- 固定场景下的报告大纲和核心结论保持稳定。

### 15.5 输出

- PPT、Excel 和 HTML/PDF 中的关键指标逐项一致；
- 输出文件可正常打开，图表、表格、中文字体和分页可读；
- 报告包含数据批次、指标版本和发布版本；
- 同一 Report Snapshot 重复生成结果不发生数值漂移。

## 16. V1 验收标准

V1 被视为完成，必须同时满足：

1. 标准 Excel 模板能够生成并成功导入；
2. 至少一个非标准 Excel 样例能够经 AI 建议和人工确认转换到标准层；
3. 模拟数据的经营和财务对账通过，转换全程留痕；
4. 高密度驾驶舱完整展示当月、YTD、预算、同比和趋势；
5. 至少完成“规模增长但盈利和现金恶化”主故事的可复核诊断；
6. 核心利润和现金 Finding 能下钻到驱动、维度、公式、标准记录和源行；
7. AI 输出不产生未经计算或验证的数字；
8. 成功生成内容一致的 PPT、分析 Excel 和 HTML/PDF 月报；
9. 阻断错误、警告、分析降级和发布重试均有可验证行为；
10. 系统不依赖特定本地离线部署方式。

## 17. 后续演进方向

V1 验证完成后，可以在不改变标准层主干的前提下扩展：

- 多文件和多数据源自动合并；
- ERP、财务系统、业务系统和 API 连接器；
- 日度与实时运营监控；
- 滚动预测、情景测算和多版本计划；
- 管理层视图和角色权限；
- Issue、Action、Owner、Deadline 和 Outcome 闭环；
- Word 报告、更多 PPT 模板和企业品牌模板；
- 更多行业数据包、指标域和 Investigation Playbook。

## 18. 命名约定

首版工程和产品工作名称统一使用 **FLOW**。它代表一个围绕财务逻辑、经营分析和工作流组织的工作空间。正式品牌释义不影响 V1 产品设计和实施，留到品牌阶段单独确定。
