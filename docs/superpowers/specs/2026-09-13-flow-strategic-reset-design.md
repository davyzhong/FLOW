# FLOW 战略重构与 AI 财务分析工作台设计

## 1. 决策摘要

FLOW 的核心产品目标调整为：

> 面向单个企业内部财务经营分析团队的 AI 财务分析工作台，帮助经分专员从原始 Excel 和企业数据出发，自动完成月度财务经营分析的大部分工作，形成有证据、可追溯、接近可发布的交互式报告；最终由经分专员一次审核后正式发布。

企业内部分析工作台是最终目标产品。公开财报分析不删除，但从 FLOW 主工作流中分离为独立模块，用于先行成熟共享的财务事实、指标、计算、证据、Finding 和报告底座。

本设计定义目标态和迁移原则，不声称这些目标能力已经实现，不授权在 U8 收口前开展核心数据模型、主导航或月度工作流的大规模代码改造。

## 2. 为什么需要重构

项目已经形成数据接入、财务事实、指标治理、确定性分析、Investigation、报告冻结、多格式输出、公开财报分析和经营概览等大量能力，也积累了静态财务/经营知识库。与此同时，几次方向调整使产品主角色、公开财报与企业内部场景、财务与经营模块、当前路线图之间出现了不一致：

1. README 和产品文档仍把 Finance BP 描述为主要分析操作者；
2. 公开财报的阶段性验证路径占日益接近产品定位本身；
3. 数据、分析、调查和报告能力分散在多个页面，用户需要自行拼接完整工作；
4. 指标、公式、科目、证据与配置已经是核心资产，但“专业治理可见性”尚未成为明确产品价值；
5. 旧计划把 U9/U10 作为 U8 后的自然后继，本轮讨论确认 U8 后必须先重新裁决路线。

本次重构不否定既有工程资产，而是重新确定其在目标产品中的职责。

## 3. 产品目标与非目标

### 3.1 核心工作

第一完整场景是月度综合财务经营分析：

```text
收集资料
→ 识别与映射
→ 校验与对账
→ 自动标准扫描
→ 推荐重点
→ 深入调查
→ 补充证据
→ 分析型 AI 生成专业版
→ CFO 角色 AI 生成管理层版
→ 经分专员一次终审
→ 正式发布
```

主交互按可见、可追踪的月度工作流组织；对话是任一阶段追加调查、解释或修改的辅助入口，不取代工作流状态和正式对象。

默认流程中系统完成标准扫描并推荐重点；经分专员可以接受、调整或追加调查，再进入深入调查与补证。系统目标是完成典型报告 80%–90% 的工作；经分专员主要核对证据、处理少量例外并一次性批准发布（人工工作量不超过传统流程的 20%，见 §14 效率验收）。

### 3.2 非目标

- 不建设总账、记账或 ERP 替代系统；
- 不把 FLOW 收缩成 BI 看板或 AI 写作工具；
- 不把责任人、改善目标、截止期限和任务追踪作为首版核心；
- 不建设公共多租户 SaaS、计费或模板市场；
- 不允许 AI 绕过经分专员自行发布；
- 不允许模型生成的数字直接进入正式事实层；
- 不在 U8 完成前重构核心产品代码。

## 4. 用户与责任

| 角色 | 产品责任 | 首版权限边界 |
|---|---|---|
| 经分专员 | 核心操作者、例外处理者、最终发布责任人 | 管理企业空间和月度周期；核对关键证据；一次终审发布 |
| Finance BP | 数据和业务背景提供者 | 使用受限入口上传资料、补字段、回答问题、查看退回原因；不进入完整分析工作台 |
| 分析型 AI | 主要分析生产者 | 调用确定性工具、组织调查、形成 Finding 和财务专业版 |
| CFO 角色 AI | 管理层视角审查者 | 质疑证据、判断重要性、压缩细节、生成管理层版；不得改变事实或证据等级 |
| CFO | 首要阅读者 | 阅读最终报告；首版不作为系统发布的必经人工节点 |
| 管理层/业务负责人 | 最终价值承接者 | 主要消费发布的交互报告或派生版本 |
| 财务规则负责人 | 正式规则治理者 | 审批影响正式计算的企业级规则变更 |

## 5. 三层、两模块的目标结构

### 5.1 可见的专业治理底座

专业底座既是运行规则，也是外显产品功能：

- 财务事实、会计科目和取数定义；
- 指标、公式、维度、比较和差异分解；
- 分析方法、证据等级、置信度与发布资格；
- 企业字段映射、管理口径、阈值和报告模板；
- 知识来源、适用范围、版本、变更和被哪些报告使用。

治理分层：

1. 平台级规则只读，随正式版本发布；
2. 企业级规则可配置、可版本化；
3. 影响正式计算的规则变更必须审批；
4. 个人显示偏好可以直接生效；
5. 历史报告绑定当时版本，不能被新规则回写改变。

任何正式数字和 Finding 都应能从报告回到规则、公式、来源和版本；专业规则不得只存在于模型提示词或隐藏代码中。

### 5.2 共享分析底座

共享底座包括：

- 文件接入、画像、映射、清洗、质量与对账；
- 标准事实、期间、单位、主体、范围和血缘；
- 确定性指标、比较、守恒和差异分解；
- AI 探索性分析、程序复算和规则晋升；
- Finding、证据、假设、补证问题、置信度和审阅事件；
- 专业版、管理层版、终审、冻结、发布和多格式导出；
- 身份、权限、审计、存储和运行保障。

共享底座提供稳定对象与接口，不承载某一模块专属的页面叙事。

### 5.3 企业内部分析工作台

这是目标产品。每家部署企业拥有一个持续存在的企业分析空间，空间内按月创建独立分析周期，并积累：

- 科目和字段映射；
- 企业管理口径和报告偏好；
- 历史分析、已确认规则与反复出现的问题；
- 每期输入、事实、Finding、报告和冻结版本。

首版输入以企业已持有的复杂 Excel 文件包为主，未来再增加 ERP、财务系统、业务系统和数据仓库连接。当前确认的最低常见输入为：财务报表或科目余额、实际与预算、上年同期与上月、应收/回款/现金。

### 5.4 公开财报分析模块

公开模块保留在同一仓库，但具有独立入口、规格、路线图和验收。它不是企业内部工作台的导航分支，也不定义内部用户角色。

公开模块优先用于成熟共享底座，阶段出口是：自动完成公开材料接入、事实计算、Finding、交互式报告、人工复核、冻结和导出，使报告达到接近可发布状态。

允许使用四级材料：

1. 财务报表与附注；
2. 完整定期报告，包括管理层讨论、业务分部和风险；
3. 公司公告、业绩说明会和投资者材料；
4. 新闻、研报和其他网络资料。

材料等级不得被抹平；低等级资料只能作为低等级证据或调查线索。

物流供应链是第一验证样板，不是长期行业边界。

## 6. 报告与 Finding 合同

### 6.1 报告形态

- 固定骨架保证月度连续性；动态专题承载当期重要问题；
- 财务结果和经营指标都属于固定分析对象；
- 交互式报告是权威母版；PPT、PDF、Excel 等是冻结母版的派生发布物；
- 财务专业版保存完整口径、证据和不确定性；管理层版调整重点与表达，但必须与专业版事实一致；
- 两个版本的删改、证据和理由必须可追溯。

### 6.2 Finding 最低完整度

核心 Finding 必须包含：

1. 变化事实；
2. 驱动因素；
3. 财务影响；
4. 支撑证据；
5. 风险判断；
6. 建议动作。

首版不强制责任人、改善目标和截止期限，避免把产品扩张为任务管理系统。

### 6.3 事实、假设与结论

- 数据直接证明的内容可以成为事实；
- 证据不足的业务原因保持候选假设；
- 重要假设触发补证请求；
- Finance BP 或经分专员的说明可以作为“人工提供的业务证据”，不得伪装为系统事实；
- 只有证据充分且置信度达到门槛，假设才能升级为正式结论；
- 风险大小影响审阅优先级和阈值，但不代替证据充分性判断。

## 7. 证据和知识使用原则

企业事实、项目静态知识和外部参考是三类不同资产：

| 层级 | 主要作用 | 不得越界 |
|---|---|---|
| 企业事实 | 证明本期发生了什么 | 不完整时不得靠行业经验补造 |
| 项目静态知识 | 提供分析方法、指标结构和审查规则 | 不能自动成为企业事实 |
| 行业/外部参考 | 提供比较、背景、候选解释和建议启发 | 低权威材料不能覆盖企业证据或正式规则 |

报告必须显示每项证据的类型、来源、期间、适用性和权威级别。用户能从结论回到原始事实、计算和引用材料。

动态 Obsidian 不作为运行时依赖；项目默认使用已经发布的静态知识版本。建立新知识截面或知识发布必须由独立维护任务明确授权。

## 8. 确定性计算与 AI 探索的分层组合

### 8.1 正式计算

正式指标、比较、差异和标准分解由确定性财务引擎产生，包含版本化公式、明确输入、期间/单位/范围、精度和缺失处理。同一输入和同一规则版本必须得到同一结果。

### 8.2 探索性计算

AI 可以在调查区提出新公式、临时分组和新拆解，但必须：

1. 声明输入、公式、口径和目的；
2. 由程序重新计算；
3. 通过期间、单位、范围、守恒和缺失检查；
4. 在未晋升前保持 exploratory，不得成为正式指标；
5. 经反复验证和财务规则负责人审批后，才能进入版本化规则库。

算术复算通过不等于财务含义正确；适用性仍需规则或人工审查。

## 9. 企业记忆与自动学习

可以自动复用：字段映射、科目映射、计算口径、已批准规则、报告结构和显示偏好。

不得直接复用：历史业务原因、责任判断、一次性解释和建议。它们只能进入候选假设池，由系统寻找本期证据后重新确认。

规则、事实和情境解释必须分别存储。历史修订采用追加版本和审阅事件，不能静默覆盖。

## 10. AI 报告生产链

### 10.1 分析型 AI

调用可审计的数据与计算工具，执行标准扫描、重点推荐、调查、补证和 Finding 组装，生成财务专业版。它不能自行创造正式数字或隐去缺失证据。

### 10.2 CFO 角色 AI

以管理层视角执行第二次独立审查：

- 挑战证据是否支持结论；
- 检查现金、预算、盈利和重大风险是否遗漏；
- 判断管理重要性和报告主线；
- 压缩技术细节并生成管理层表达；
- 保留专业版到管理层版的差异和理由。

它不能修改确定性事实、把假设改成事实、提高证据等级或批准发布。

### 10.3 经分专员终审

终审界面按例外和高影响内容组织，而非要求重新通读和重做全部分析。经分专员处理关键证据、未闭合问题和 AI 角色间冲突后，一次性批准正式发布。

## 11. 部署、安全和模型边界

- 当前目标是公有云企业单租户，不承诺公共多租户 SaaS；
- 企业数据、配置、知识上下文、对象存储和审计日志必须隔离；
- 允许使用具备企业数据保护条款的云模型 API；
- 模型调用必须最小化数据范围、禁止训练、记录用途/模型/输入边界/输出和工具调用；
- 原始明细是否发送由企业策略控制，敏感内容遵循脱敏和最小权限；
- U8 的 HTTPS、存储、发布、恢复和运行验收是后续大规模改造的前置基线。

## 12. 失败与降级行为

| 情况 | 必须行为 |
|---|---|
| 输入缺失或映射不确定 | 阻止受影响计算；继续完成可证明部分；生成精确补充请求 |
| 对账不闭合 | 显式显示差异和影响；不得发布受影响事实 |
| 业务原因无本期证据 | 保持候选假设，不继承历史结论 |
| AI 临时计算无法复算 | 丢弃该数字并保留失败记录 |
| 两个 AI 角色结论冲突 | 提交经分专员的例外队列，不自动择一 |
| 外部资料冲突 | 显示来源等级、时间和冲突；企业事实与高权威规则优先 |
| 云模型不可用 | 保留已完成确定性结果和工作流状态；不伪造 AI 完成 |
| 发布后规则变化 | 新周期使用新版本；旧报告和证据保持冻结 |

## 13. 执行顺序

### 阶段 0：完成 U8

先完成真实存储旅程、发布、HTTPS、部署、恢复和运行验收，形成一个完整、可运行、可恢复的现有版本。战略设计与文档治理可以并行，但不开展大规模产品代码重构。

### 阶段 1：冻结版本并重构边界

冻结 U8 完成版本，建立共享专业底座、公开模块、内部工作台的清晰模块边界和独立规格。重新裁决旧 U9/U10，不机械续跑。

### 阶段 2：公开模块达到阶段出口

补齐多级公开证据、自动 Finding、分析型 AI、CFO 角色 AI、交互式报告、例外终审、冻结与导出。达到接近可发布后，主要资源切换到内部工作台。

### 阶段 3：企业内部月度工作台

建立持续企业空间、月度分析周期、Finance BP 轻量提交入口、企业配置、历史学习和双版本报告。

### 阶段 4：四级验证

```text
物流样板端到端
→ 专业经分人员评审
→ 与人工报告和工作量对照
→ 授权脱敏真实企业数据最终验证
```

## 14. 验收体系

| 层级 | 验收重点 |
|---|---|
| 数据 | 完整性、映射、期间、单位、主体、范围、勾稽和来源 |
| 计算 | 确定性复算、守恒、版本冻结、历史报告不漂移 |
| 分析 | Finding 六要素；事实/假设/结论分离；补证闭环 |
| AI | 输入和工具可审计；角色边界；冲突和降级可见 |
| 报告 | 固定骨架+动态专题；专业版与管理层版事实一致；差异可解释 |
| 产品 | 工作流可连续完成；专业治理高度可见；对话不绕过状态 |
| 效率 | 典型月报人工工作量不超过传统流程的 20% |
| 最终 | 授权脱敏真实数据通过，专业经分人员确认质量不低于人工基准 |

最终门槛任一项未达到，不自动扩大产品范围；必须记录问题属于修正、收缩、推迟还是停止条件。

## 15. 对现有文档与路线图的影响

本设计获批后：

- D002、D010、D039、D045、D046、D049 中与新目标冲突的部分由新决策接替或修订，历史事实保留；
- `PRODUCT_VISION`、`PRODUCT_SCOPE`、`USER_AND_WORKSPACES`、`PRODUCT_BOUNDARIES`、`RELEASE_SCOPE` 和 `CAPABILITY_MAP` 必须区分已实现与目标态；
- 新增 `PRODUCT_PRINCIPLES`，固定用户、证据、计算、AI、治理和发布原则；
- `CURRENT_ROADMAP` 保持 U8 active，但 U8 后新增战略边界重构门禁，U9/U10 改为待重新裁决；
- README 和导航只提供摘要与权威链接，不复制整份设计；
- 公开财报能力不删除、不降格为历史，但不再代表 FLOW 的最终产品定位。

## 16. 延后决定

以下内容不在本设计中提前确定：

- 企业连接器的具体优先顺序；
- CFO 角色 AI 的模型供应商和提示实现；
- 置信度数值算法与各类结论阈值；
- 企业规则审批的具体组织角色名称；
- 内部工作台的详细页面布局；
- 是否以及何时演进为多租户商业产品。

这些事项应在 U8 完成后的子规格中逐项设计和批准。
