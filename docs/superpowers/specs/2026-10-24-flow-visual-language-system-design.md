# FLOW 可移植视觉语言与全项目视觉统一设计

## 1. 目标

从用户确认的 2026-10-18 A+C 概念板中提炼一套可复用的 FLOW 视觉语言，并将其应用到 FLOW 的全部产品视觉表面。它应能在未来项目中独立复用，不依赖当前驾驶舱页面结构或特定图表库。

## 2. 视觉方向

以「高管编辑部」和「财务报告画布」为统一方向：稳重、温暖、精确、克制，先呈现财务结论，再呈现支持证据与口径。概念板是视觉参考，不是数据来源；示意数值、结论、阈值和虚构企业事实不得进入产品。

### 2.1 颜色与材料感

- 以柔和纸白作为主背景，以深海军蓝承担品牌、导航、标题和重要结构。
- 古金用于品牌与有限的强调，不用作普遍的状态色或大面积装饰。
- 经营数据序列采用稳定的蓝、金与中性墨色；正负、警告、缺失和不可用状态沿用明确的语义色和文字说明，不能靠颜色单独区分。
- 用细分隔线、低对比表面和轻微层次构成纸面报告感；减少大面积纯蓝底、高饱和渐变、厚阴影和过度圆角。

### 2.2 字体与数字

- 中文大标题采用高可读衬线字体栈，正文和控件使用清晰的无衬线字体栈。
- 财务值使用稳定的数字宽度、对齐方式和单位层级；代码、ID、哈希等机器标识用等宽字，不把所有内容强制为单一字体。
- 字体缺失时使用跨平台回退栈；不依赖网络字体才能读懂页面。

### 2.3 信息结构与视觉表达

将概念板的表达抽象为模式，而非复制某一张总览：

1. **编辑部页眉**：明确结论主题、期间、数据性质与简短导语；筛选器退居次级。
2. **核心指标卡**：控制首屏指标数量，显示数值、单位、比较期间和变化语义。
3. **趋势与对比图**：标题说明问题，图例、坐标、单位和期间完整；必要时在末端直接标注值。
4. **守恒/驱动桥**：用清晰的起点、变化项和终点讲述数值如何形成；未知项不填零。
5. **结构与拆解图**：杜邦、费用、资产结构等图保留分解关系和同值支持表。
6. **洞察与行动卡**：先陈述证据和口径，再呈现判断、限制与下一步。
7. **来源与口径面板**：稳定展示数据来源、事实类别、更新时间、单位和计算口径，并可追溯到支持记录。
8. **移动端阅读流**：标题和结论前置，指标保持可读，多系列图允许横向内容本身自适应但页面不能横向溢出，来源与支持表仍可访问。

## 3. 可复用交付形态

交付一个跨技术栈可复制的视觉语言包，作为未来项目的设计参考和实现起点：

- 规范文档说明视觉原则、字体、颜色语义、排版、间距、层次、图表表达、响应式、可访问性和禁用情形。
- 单一 token 清单记录颜色、字体、间距、边框、圆角、阴影和图表系列的语义名称与取值。
- CSS token 文件供 Web 项目直接复制；非 Web 项目通过相同语义名称映射到自己的样式系统。
- 模式手册为上述页面/图表表达提供用途、结构、适用边界与示例；不把 FLOW 业务数据绑定进通用样式。
- 不创建外部发布、npm 包或新运行时依赖。新项目能够复制视觉语言包后独立采用，不要求加入 FLOW monorepo。
- FLOW 当前 Web 主题以视觉语言 token 为唯一颜色/字体源；报告渲染器将语义 token 映射到 HTML/PDF/PPTX 主题。若跨语言单一 token 自动生成会引入重复真相或构建复杂度，先采用文档化映射并加入一致性校验，不为抽象而抽象。

## 4. 应用范围

### 4.1 产品页面

覆盖 `apps/web/app` 中的全部 20 个页面路由：经营总览、8 个 CFO 驾驶舱路由、数据工作台、分析、调查列表与详情、指标库、运营、报告、财报、公开资料、内部工作台、首页和登录页。登录页保持独立认证流程和必要的轻量布局，不强制套用主应用导航，但须符合相同的品牌、字体、配色和控件语言。

### 4.2 图表与其他输出

- 检查并统一 Web 上所有图表、支持表、筛选区、状态页、抽屉和空/错/加载/降级状态。
- 纳入用户可见的报告/出版输出：HTML、PDF、PPTX 与 XLSX；依格式能力适配，不为表格型 XLSX 强造装饰图表。
- 同步本机离线总览与报告预览、README 中的产品导览/流程图/截图说明等视觉材料。
- 只更新当前有效、面向用户或维护者且描述现状的文档。历史归档、原始资料、不可变档案、旧验收截图和外部来源原件保持原状；新增截图须准确标识代码 SHA、数据批次、视口和示意/合成数据限制。

## 5. 全项目应用原则

- 内容层级、样式 tokens、组件模式和数据事实分离；样式包不得计算、改写或推断业务事实。
- 先统一共享设计变量和基础外壳，再按页面任务调整构图；不把每页强制做成总览卡片布局。
- 保留现有 ECharts、表格、组件和标准字体资源。除非审计证明确有必要，不引入新的图表库、CSS 框架、字体服务或全局依赖。
- 正值、负值、零、缺失、降级、模拟、披露及预测数据保留原有业务语义和明示标签。
- 可访问性至少覆盖文字/控件对比度、键盘焦点、可见标签、颜色之外的状态线索、图表等价值表与 200% 缩放阅读。

## 6. 验收标准

1. 新视觉语言包可独立复制；至少一份中文规范、一份 token 源、一份 CSS 交付和一份组件/图表模式手册，注明授权范围与版本方式。
2. 全部 20 个路由在隔离演示数据或有据可查的空/错误场景下完成视觉盘点；桌面 1440、平板 1024、手机 390 三种宽度均检查。动态调查详情使用真实隔离 Finding 标识。
3. 每个图表和数据表达均进入差距清单并有结案状态：符合、调整、数据受限或不适用；不得只按页面抽样。
4. 全部图表标题、期间、单位、图例、事实类别、同值支持表和来源/口径说明符合页面合同；数据不足的分析保持明确限制。
5. HTML/PDF/PPTX/XLSX 发行视图与 Web 采用同一视觉语义，字号、纸面背景、标题层级、图表色义、来源和事实边界不冲突；Excel 数值仍可筛选、复制和审计。
6. 首尾对照截图及差距矩阵可追溯到当前代码 SHA 与隔离数据批次；截图没有浏览器错误、页面级横向溢出和外网资源依赖。
7. 全部适用页面的视觉回归、键盘/缩放/对比度检查通过；相关前端测试、类型检查、生产构建、报告渲染器定向验证、M1/M6 与文档链接检查通过。
8. README、文档中心、当前状态、路线图、交接、页面/运行/报告说明和截图索引不再陈述 7a 仍在执行；按最终实现说明新的视觉语言、全部覆盖情况、限制和可复用方法。
9. 独立复核只报影响正确性或既定验收的 P1/P2 缺口；不得把风格偏好扩张成无限重构。

## 7. 风险与不在范围内的事项

- 「尽可能接近」以视觉原则和表达模式一致为准，不逐像素仿制示意图；真实数据和限制优先于图像外观。
- 既有页面、图表和报告规模较大，按当前唯一队列内的串行小切片完成；页面差异和未验证项登记，不以全局 CSS 覆盖隐藏问题。
- 不修改数据库 schema、迁移、CI/CD 工作流或发布流程；不重启 GitHub 截图自动化。
- 不删除旧截图、旧 README 视觉材料或历史文档；由索引区分 current 与 historical。
