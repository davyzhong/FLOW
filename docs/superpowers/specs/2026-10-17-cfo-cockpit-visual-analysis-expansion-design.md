# CFO 驾驶舱图表与客观财务分析增强设计

## 1. 目标与范围

在不重做已验收驾驶舱图表的前提下，补齐数据充分但目前缺少可视呈现的财务关系，交付一个可追溯的盈利能力分析页面，重点呈现杜邦三因子。页面继续服务 CFO/BP 的客观财务分析，不加入主观原因推断、预测、预算编制或任意自助 BI。

采用用户选择的推荐方向 A「图表分析画布」：保留并复用已验收的总览趋势、期间比较、资产结构及 51 图映射；仅对实际页面截图和 API 数据核对后仍缺失、且已发布事实足够的视图补齐。新增盈利能力页面提供杜邦驱动、利润率及 ROE 因子比较。现有费用、资产负债、营运资金、现金流、风险和合并模块不重复建设已有图表。

## 2. 当前基线与问题

- 当前驾驶舱已有总览趋势与多模块图表，51 图覆盖映射与 8 张页面截图均已验收；最新某隔离截图中总览趋势面板显示暂无可用数据，不能据此推断所有运行数据均缺失。
- 仍待补齐的明确缺口是：盈利能力没有独立路由；已有 `buildDupont` 构建器和指标库中的杜邦关系尚未接入该页面；模块/总览中只对页面和数据实测确认的缺口纳入本任务，其余作为已交付能力保留。
- 仓库已使用 ECharts 6.1.0，已有柱线组合、瀑布、环图、矩阵和 `buildDupont` 杜邦树构建器；不新增图表库。
- 已核实的公开财报完整期间为 FY2022、FY2023；这些数据适合真实双期比较，不足以称为多年长期趋势。缺少期间不得补零或生成貌似真实的长序列。
- 财务指标定义以 `config/metrics/metric_dictionary_v1_1.yaml` 和现有 Decimal 公式引擎为唯一事实源，不复制公式或改写口径。

## 3. 设计

### 3.1 总览图表画布

保留来源提示、筛选器、KPI 卡、结论与行动区。在 KPI 下增加以实际可用数据驱动的图表网格：

1. 收入、成本、毛利/净利润的期间对比图；不同量纲使用组合图的双轴或分图，不共用误导性坐标轴。
2. 经营、投资、筹资现金流与自由现金流的期间比较或现金变化桥；缺少构成项时展示 available/unavailable 口径，不绘制不完整的瀑布。
3. 资产/负债/权益结构图及关键偿债比率比较。
4. 若现有总览没有杜邦入口，增加通往盈利能力页的明确导航/卡片，不另建重复图表或单独取数路径。

总览一次请求读取聚合视图所需的数据；禁止逐图请求。若接口需要扩展，作为同一聚合响应的可选视觉载荷或复用单个模块聚合端点。

### 3.2 盈利能力与杜邦分析页

新增 `/cockpit/profitability`，使用 `<AppShell>` 并登记到 `workflow-nav` 与路由守护测试。页面包含：

- 杜邦分解树：`ROE = 净利率 × 总资产周转率 × 权益乘数`；每个节点显示当前值、可比前期、单位、期间、来源和口径。
- FY2022/FY2023 因子对比图与利润率趋势图；标明这是两期年度比较，不作长期趋势判断。
- 因子公式与可复算值表；ROE 与因子乘积之间的勾稽差异必须在舍入容差内，否则显示校验失败，阻止显示为已验证。
- 因子可链接到指标库定义和原始财报行；在没有权限或证据支持的细粒度数据时，不提供伪下钻。

### 3.3 口径与数据边界

- ROE 使用归属口径一致的净利润与平均权益；净利率用同口径净利润/营业收入；总资产周转率用营业收入/平均总资产；权益乘数用平均总资产/平均权益。若指标字典定义对主体/期间另有明确要求，服从字典并展示口径标签。
- 资产/权益平均数必须具备期初与期末值。缺少期初、期末、分子/分母映射不明、分母为零或期间不一致时，该因子显示不可用，不以期末值代替平均值。
- 页面数值必须复用已发布 `MetricSnapshot` / `ReportSnapshot`，或客观财报不可变 `ObjectiveReportSnapshot` 中的值。允许扩展现有 Objective 快照 payload，在快照创建时按指标字典定义计算并冻结指标值、定义版本、计算轨迹及源行锚点；Cockpit 页面和读取 handler 不得重算。每个数值携带对应快照身份和来源报告身份，前端拒绝渲染缺少快照身份的数据。杜邦一致性校验在冻结阶段计算并保存，读取阶段仅展示结果。
- 财务比较仅使用已发布、可溯源的披露事实或经登记、可复算且与披露总额勾稽的派生值。演示生成明细必须显式标记为演示数据，不能写成菜鸟实际逐月数据。
- 所有图表提供单位/期间 tooltip 与可访问的数据表；颜色不作为唯一的涨跌表达；缺失点保持断点，格式遵守计数整数、金额两位小数、百分比/倍数按既有格式规则。

## 4. 技术架构与复用

- 前端复用 ECharts 6.1.0、`components/cockpit/charts/builders.ts`、`module-options.ts`、`ChartBox`、数字格式器与现有页面状态组件。
- 后端优先复用已发布快照与现有指标读取/发布链；不得在 `ModuleFactContext` 或 cockpit 路由里从规范化报表行重算页面比率。扩展 Objective 财报快照的 JSON payload schema version（数据库表结构不变），在显式冻结动作中记录指标计算结果和血缘；既有 v1 快照保持只读兼容且盈利图表标记 unavailable。读取通过单一盈利能力聚合端点提供，沿用 `Action.DASHBOARD_OVERVIEW_READ` 单企业边界。
- API 权限复用已批准的 `Action.DASHBOARD_OVERVIEW_READ` 和单企业范围 loader；不修改安全角色、迁移或 CI 配置。
- 不引入新的图表依赖、不重复实现通用绘图、不创建平行指标定义。

## 5. 验收

1. 对照现有验收与当前隔离数据复核总览，不重复实现已交付图表；确认仍有图表缺口时仅补齐已有冻结数据充分支持的部分，其余明确标注不可用。
2. 新盈利能力页真实渲染杜邦树、因子比较图和公式表，ROE 勾稽通过；因子链到指标定义及报告来源。
3. 所有新增图表的数值、单位、期间、数据可用状态与 API 数据一致；不存在补零、虚构期间、错误轴尺度或未标注的示意数据。
4. 导航、AppShell、键盘/读屏替代表、深链、加载/空/错误态、窄屏布局和来源链接均有测试。
5. 使用隔离财报样本和隔离数据库验收；不连接或重置常驻开发/演示库。
6. Web/API 定向测试、类型检查、lint、生产构建、路由矩阵、Playwright 截图、文档门禁和准确提交 SHA 的 GitHub CI 通过。

## 6. 明确不做

- 不增加预测、预算、行业分位、因果归因、管理建议或主观诊断。
- 不以一条双期折线声称长期趋势；不为视觉完整而填补未披露数据。
- 不删除或替换已交付驾驶舱页面，不变更现有租户权限、审计或财务事实源。
