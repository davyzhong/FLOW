# FLOW AI 自然语言问数方案

> 所有头部竞品都在做（AlphaSense / Hebbia / Wind GPT / 通联萝卜投研）。FLOW 必须补。
> 本文给出详细架构设计 + 模型选型 + 评测方案。

## 一、产品定位

**目标**：让企业财务分析师用自然语言查询 FLOW 的事实库 + 指标字典 + 文档，AI 给答案 + 引用 + 可点击跳转。

**核心场景**：

1. 单公司问数
   - "顺丰 2026Q1 的净利率为什么比 2025 年低？"
   - "腾讯最近 4 个季度的 ROE 趋势如何？"
   - "菜鸟 FY2022 亏损原因是什么？"

2. 跨公司对比
   - "对比 5 家物流公司的运营效率"
   - "ROE 最高的物流公司是谁？"
   - "阿里 vs 京东物流：哪个的周转率更高？"

3. 反事实 / 预测
   - "如果顺丰杠杆降到 1.5x，ROE 会怎么变？"
   - "如果京东物流净利率提升 2pct，盈利能力能排第几？"

4. 报告生成
   - "基于顺丰最新数据生成一份 MD&A"
   - "给我写一段菜鸟的杜邦分析文字"

### 2.2 RAG 检索增强生成（基础）

```
用户问题 "顺丰 2026Q1 的净利率为什么下降？"
   ↓
   ① 问题向量化 (embedding: BAAI/bge-large-zh)
   ↓
   ② 多路召回:
      - 向量检索: facts 中顺丰 2026Q1 / 2025Q1 相关记录 (top-k=20)
      - 关键词检索: 顺丰 2025Q1 + 2026Q1 财务事实
      - 元数据过滤: company=sf_002352 AND period IN [2025Q1, 2026Q1]
   ↓
   ③ 重排 (cross-encoder rerank): BAAI/bge-reranker-large
   ↓
   ④ 取 top-10 事实 + 上下文
   ↓
   ⑤ LLM 生成答案 (prompt: 你是一个专业的财务分析师，引用以下事实...)
   ↓
   ⑥ 流式输出 + 引用卡片（事实 ID + 跳转链接）
```

### 2.3 Agent 多步推理（进阶）

```
用户问题 "对比 5 家物流公司的运营效率"
   ↓
   ① 问题分类 → "跨公司对比"
   ↓
   ② Agent 决策：
      - 检索"运营效率" = 资产周转率（FLOW 指标字典里有）
      - 列出 5 家公司的资产周转率
      - 计算行业均值 / 标杆 / 末位
      - 加入"业务模式"上下文（顺丰直营 vs 通达系加盟）
   ↓
   ③ 多步 Tool Use:
      - lookup_facts(company IN [sf, jdl, cainiao, ...], item_id=is.revenue, role=cur)
      - lookup_facts(company IN [...], item_id=bs.total_assets, role=end)
      - calc_metric("asset_turnover", company IN [...])
   ↓
   ④ 综合生成：
      "5 家物流公司的资产周转率对比如下：
       顺丰 2026Q1: 0.347x（直营时效模式，单票均收入高）
       京东物流 FY2025: 1.74x（仓配一体化，资产较轻）
       ..."
   ↓
   ⑤ 每个公司给出引用 + 跳转链接
```

## 三、模型选型

### 3.1 国内开源（推荐私有部署）

| 模型 | 上下文 | 性能 | 推理速度 | 私有部署 | 推荐度 |
| --- | --- | --- | --- | --- | --- |
| **Qwen2.5-72B-Instruct** | 128K | ★★★★★ | 快（vLLM） | ✅ | ⭐⭐⭐⭐⭐ |
| DeepSeek-V3 (671B MoE) | 64K | ★★★★★ | 中（需 4x A100） | ✅ | ⭐⭐⭐⭐ |
| Qwen2.5-7B-Instruct | 128K | ★★★ | 极快 | ✅ | ⭐⭐⭐（轻量版）|
| Llama-3.3-70B-Instruct | 128K | ★★★★ | 中 | ✅ | ⭐⭐⭐（备选）|
| Qwen2.5-Coder-32B | 64K | ★★★★（代码强）| 快 | ✅ | ⭐⭐⭐（SQL/分析专用）|

**推荐**：Qwen2.5-72B-Instruct 作为主力模型。

理由：
- 国内开源，中文财报语料训练充分
- 128K 上下文，可一次性塞入 5 家公司所有事实
- vLLM 推理快
- 商业可用（Apache 2.0 协议变种）

### 3.2 云端模型（高准确率）

| 模型 | 上下文 | 性能 | 价格 | 推荐场景 |
| --- | --- | --- | --- | --- |
| GPT-4o | 128K | ★★★★★ | $5/$15 per 1M tokens | 高准确率场景 |
| Claude 3.5 Sonnet | 200K | ★★★★★ | $3/$15 per 1M tokens | 长文档分析 |

## 四、数据准备

### 4.1 检索文档源

| 文档 | 数量 | 切分策略 |
| --- | --- | --- |
| 事实 facts | 670 条 → 目标 5000 条 | 每条作为独立 chunk |
| 指标定义 | 64 指标 × 5 字段 | 每个指标的"定义 + 取数 + 公式"作为 chunk |
| 报告原文（顺丰等） | 14 份 → 目标 80 份 | 按"章节 + 段落"切分 |
| 治理记录 | 50 条 | 每条事件一个 chunk |
| 行业基准 | 待补 | 行业 × 指标 × 中位数 |
| 文档（management discussion） | 待补 | 段落切分 |

### 4.2 Chunk schema

```python
class Chunk(BaseModel):
    id: str                    # 唯一 ID
    source_type: str            # fact / metric / report / governance / industry
    source_ref: str             # 原始来源（文件名 / item_id / doc_id）
    company: Optional[str]
    period: Optional[str]
    item_id: Optional[str]
    text: str                   # 检索文本
    metadata: dict              # 其他元数据
    embedding: List[float]      # 向量
```

### 4.3 向量化策略

- 每条事实 / 指标的"自然语言描述"作为 embedding 输入
- 元数据（company / period / item_id）用于 metadata filtering
- 检索时先 metadata filter（缩小范围），再向量检索（排序）

## 五、Prompt 设计

### 5.1 系统 Prompt（中文）

```
你是 FLOW 平台的财务分析师助手，专门帮助企业用户解答财报分析问题。

# 你的能力
1. 查询 FLOW 事实库（已抽取的财务事实）
2. 计算杜邦因子和其他财务比率
3. 跨公司对比
4. 行业基准对比
5. 引用原财报 PDF

# 你的限制
1. 只能基于 FLOW 提供的事实回答，不能编造
2. 每个数字必须标注来源
3. 不确定的要明确说"未抽取"或"数据缺失"
4. 不输出投资建议，只做事实陈述

# 回答格式
- 先给结论（1-2 句话）
- 给出关键数据 + 公式 + 来源
- 给出引用（链接到具体财报 / 事实）
- 如有多个解读角度，分别列出

# 输出语言
中文（除非用户用英文提问）
```

## 六、评测方案

### 6.1 评测维度

| 维度 | 定义 | 量化指标 |
| --- | --- | --- |
| **正确性** | 数字是否对 | 误差率 < 5% |
| **可解释性** | 每个数字可溯源 | 100% 数字有 fact_id |
| **完整性** | 是否答完所有子问题 | 完整率 ≥ 95% |
| **事实一致性** | 引用是否真实存在 | 引用准确率 100% |
| **语言流畅性** | 中文是否通顺 | LLM 评分 ≥ 4/5 |
| **响应时间** | p95 延迟 | < 3s |

### 6.2 评测数据集（v1）

构造 100 条问数（覆盖 5 类场景）：

| 场景 | 数量 | 示例 |
| --- | --- | --- |
| 单公司问数 | 40 | "顺丰 2026Q1 的 ROE 是多少？" |
| 跨公司对比 | 25 | "对比 5 家公司的资产周转率" |
| 趋势分析 | 15 | "腾讯 2Q2026 的同比收入增长？" |
| 反事实 | 10 | "如果京东物流净利率提升 2pct" |
| MD&A 生成 | 10 | "给顺丰 2026Q1 写一段分析文字" |

每条问题配套：
- 标准答案（人工撰写）
- 引用列表（预期被引用的事实 ID）
- 评分标准

### 6.3 自动评测 + 人工抽检

```
1. 自动评测（每日跑回归）
   - 100 条问题 × 3 个模型 = 300 个样本
   - 计算每个模型的 6 个维度分数
   - 不达标的进 issue 跟踪

2. 人工抽检（每周）
   - 抽 20 个真实用户问数
   - 资深分析师评分（5 分制）
   - 用户反馈 → 改进 prompt

3. A/B 测试（每月）
   - 模型 A vs 模型 B 各 100 个样本
   - 胜出模型上线
```

## 八、安全与合规

### 8.1 数据不出本地（私有部署）

- LLM 必须支持本地部署（Qwen / DeepSeek）
- 向量库本地（pgvector / Chroma）
- 不允许调用外部云端 LLM API

### 8.2 数据脱敏（云端模型 fallback）

- 调用 GPT-4o 前先脱敏：公司名 / 金额 / 比例
- 脱敏规则：
  - 公司名 → 公司代号
  - 金额 → 仅显示精度（如 "X.X 亿元"）
  - 比例 → 保留（如 "X.X%"）
- 输出结果只显示聚合结论，不显示原文

### 8.3 审计日志

```
每次问数记录:
- 用户 ID
- 问题文本
- 检索到的事实 ID 列表
- LLM 模型版本
- 输出答案
- 时间戳
- 用户反馈（点赞 / 点踩）
```

### 8.4 权限控制

- 复用现有 FLOW 权限系统（`apps/web/app/api/auth/`）
- 限制：分析师可访问所有数据；高管只访问汇总；审计可访问全部历史
- RLS（行级安全）按团队 / 项目
