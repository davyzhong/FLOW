# FLOW 改进与优化清单

> 配套 [summary-and-positioning.md](summary-and-positioning.md) 的"能力缺口"与"路线图"。每条按 **优先级（P0/P1/P2）/ 成本（低/中/高）/ 风险（低/中/高）/ 工作量（人月）** 分级。共 **35 条**。

## 一、P0 — 核心价值（必须做）

### 1.1 行业基准数据接入

**问题**：FLOW 当前杜邦拆解（5 家公司）没有行业对照表，"高 / 低"无法判断。

**做法**：
- 引入第三方行业基准数据：巨灵 / 通联 / 同花顺 iFinD 行业 API
- 或自建 benchmark：从 Wind / 东方财富爬取上市公司 5 年财务 → 行业聚合 → 中位数 / 均值
- 行业分桶：物流 / 电商 / SaaS / 制造 / 金融（每个 5-10 家）

| 项 | 值 |
| --- | --- |
| 优先级 | P0 |
| 成本 | 中（数据采购 / 爬虫） |
| 风险 | 中（数据合规 + 准确率） |
| 工作量 | 4-6 人月 |
| 验收标准 | 物流 / 电商 / SaaS 三个行业的"ROE 中位数 / 净利率中位数 / 周转率中位数 / 杠杆中位数"对照表；FLOW 内置 |

### 1.2 AI 自然语言问数（Q&A）

**问题**：所有头部竞品都在做（AlphaSense / Hebbia / Wind GPT / 通联萝卜投研），FLOW 没有。

**做法**：
- 第一阶段（v1）：基于事实库的检索增强（RAG）
  - 用户问"顺丰 2026Q1 的净利率为什么下降？"
  - 系统在事实库找相关 facts + 跨公司对标 + 同比环比
  - LLM 生成自然语言回答 + 引用事实 + 链接到原财报
- 第二阶段（v2）：多步推理
  - "对比 5 家物流公司的运营效率，给我一个排序"
  - 系统自动生成 SQL / 表达式，运行后输出
- 第三阶段（v3）：预测 / 反事实
  - "如果降低 0.5x 杠杆，ROE 会怎么变？"
  - 系统调敏感性模型，给出预测

| 项 | 值 |
| --- | --- |
| 优先级 | P0 |
| 成本 | 中（LLM 接入 + RAG 框架 + 评测） |
| 风险 | 中（LLM 幻觉 + 数据安全） |
| 工作量 | 8-12 人月（分三阶段交付） |
| 验收标准 | 100 条测试问数 ≥ 90% 命中率；可解释（每个回答引用事实 + 来源） |

### 1.3 数据源扩张（5 公司 → 15 公司，14 财报 → 80 财报）

**问题**：FLOW 当前覆盖太窄，无法支持行业级基准。

**做法**：
- 增加物流行业：京东物流 / 顺丰 / 中国外运 / 德邦 / 极兔 / 中通 / 韵达 / 申通 / 圆通
- 增加电商：阿里 / 京东 / 拼多多 / 美团
- 增加 SaaS：金山办公 / 用友 / 金蝶
- 增加制造：美的 / 格力 / 海尔
- 每家 5 年财报（FY2020-FY2024 + 季度）

| 项 | 值 |
| --- | --- |
| 优先级 | P0 |
| 成本 | 中（PDF 解析 + 数据 ETL） |
| 风险 | 低（已有 P5 反向解析能力） |
| 工作量 | 6-9 人月 |
| 验收标准 | 80 份反向解析财报 + 5000+ 事实；覆盖矩阵 50+ 指标 × 80 快照 |

## 二、P1 — 增强差异化

### 2.1 趋势分析（多期对比）

**做法**：每家公司扩展到 5 年历史，生成趋势图 + CAGR + 同比环比 + 移动平均。

| 项 | 值 |
| --- | --- |
| 优先级 | P1 |
| 成本 | 低（图表 + 已有数据） |
| 风险 | 低 |
| 工作量 | 2-3 人月 |
| 验收标准 | 每家公司 / 每个指标都有 5 年趋势；新增移动平均线 + 趋势判定（升 / 降 / 平稳） |

### 2.2 情景分析 / 敏感性

**做法**：杜邦拆解的"如果...那么..."动态版本
- 假设"杠杆 +0.5x"，预测 ROE
- 假设"净利率 -2pct"，预测 ROE
- 三档：悲观 / 基准 / 乐观（参考原杜邦模板）

| 项 | 值 |
| --- | --- |
| 优先级 | P1 |
| 成本 | 低（公式计算） |
| 风险 | 低 |
| 工作量 | 2 人月 |
| 验收标准 | 杜邦详情页加"敏感性分析"控件；可输入假设并即时查看 |

### 2.3 DCF / 经济利润（EVA）— McKinsey 范式

**做法**：
- 引入 DCF 框架：5 年预测 + 永续增长率 + WACC → 估值
- 引入 EVA：NOPAT - WACC × 投入资本
- 加入 FLOW 的财务分析体系

| 项 | 值 |
| --- | --- |
| 优先级 | P1 |
| 成本 | 中（建模 + 数据） |
| 风险 | 中（参数敏感 + LLM 校验） |
| 工作量 | 6 人月 |
| 验收标准 | 每家公司都能输出 DCF 估值 + EVA 趋势 |

| 项 | 值 |

| 风险 | 低 |

## 六、不要做的事（避免陷阱）

| 陷阱 | 描述 |
| --- | --- |
| 模仿 Wind 做通用金融终端 | Wind 1 万+ 指标 + 35,000 公司，FLOW 资源不够。专注垂直 |
| 模仿 Wind GPT 做云端 AI | 数据合规风险大，本地化才是中国 B 端真实需求 |
| 模仿 FineBI 做通用 BI | FineBI 团队 1000+ 人 + 多年沉淀，FLOW 做不过 |
| 模仿 AlphaSense 做海外 SaaS | 资源 / 渠道 / 人才三重不匹配 |
| 一上来做 BSC / 五力等定性框架 | 没有数据基础，定性框架是空壳 |
| 用 AI 替代分析师做"分析" | AI 应辅助而非替代；分析师最终拍板 |

## 七、监控指标

每个季度评估：
- 样本数据扩张（公司数 × 财报数 × 事实数）
- 用户活跃（DAU / MAU / 平均会话时长）
- AI 问数命中率（如果 P0-1.2 上线）
- 杜邦拆解使用率（每份财报的杜邦详情页 PV）
- 客户满意度（NPS）
- 营收（如果走 SaaS 版）
